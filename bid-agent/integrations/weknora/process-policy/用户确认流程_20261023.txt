# 招投标及投标文件制作过程
## AI辅助编制与人工审核整合稿

### 一、总体原则与职责

#### （一）制作依据

按以下顺序执行：

1. 本项目招标文件、采购文件及当前有效的澄清、补遗、修订和引用附件。
2. 经人工确认的本项目业务决定，包括投标主体、投标范围、车型配置、报价、服务承诺及指定留空事项。
3. 受保护的《标书制作全流程操作手册》。
4. 当前标书制作技能、专项技术响应规则及经确认的模板。
5. 企业资料库、客户模板库、权威库、报告级参数总表和适用的历史标书。

历史文件只能提供适用的结构、版式、成熟表达及真实资料，不能将历史项目名称、客户、价格、人员安排、日期、签章或其他配置自动带入新项目。

#### （二）完整制作目标

“先骨架、后填充”是保证结构和格式稳定的制作方法，不是只交付空白文档。

完整制作应连续完成：

**冻结输入 → 招标解析 → 骨架验收与冻结 → 按槽位匹配资料 → 资格和商务实填 → 技术选材及内部对标 → 技术与服务方案编写 → 证明附件装配 → 目录页码与文档检查 → 人工审核及交付。**

不得以分析报告、空白骨架、检索结果、内部 Excel 或检查清单代替完整投标文件。

后续仅调整技术响应方式时，不得因此削减其他商务内容、技术方案、评分章节、证明附件和制作检查。

#### （三）职责分工

| 参与方 | 主要职责 |
|---|---|
| AI／阶段 Agent | 阅读原文、识别要求、匹配资料、拟定目录、编写正文、形成对标与审查结果 |
| 程序规则与文档工具 | 固定输入、结构和槽位，校验字段、表格、原文覆盖、图片关系、版本和文件完整性 |
| 商务人员 | 确认投标范围、资格材料、业绩选择、保证金、商务条件和签署安排 |
| 技术人员 | 确认具体车型、报告配置、BOM、适配调整、技术应答及证明材料 |
| 财务及报价审批人员 | 确认成本、价格、税率、报价范围、计算结果及付款相关事项 |
| 投标负责人 | 审核整套文件、处理未决问题、批准外发和递交 |

所有 AI 输出均须经人工复核确认，才能上报审批、外发或递交。AI 不代替签字盖章、企业批准及平台提交。

### 二、项目建档、资料收集与输入冻结

#### （一）建立独立项目目录

每个项目独立保存：

1. 招标文件及全部附件。
2. 澄清、补遗、答疑和修订文件。
3. 企业原始资料及本项目采用材料的关联记录。
4. 招标解析、要求矩阵和评分台账。
5. 空白骨架、槽位清单及冻结记录。
6. 分阶段填写稿、人工修订稿和历史版本。
7. 内部技术对标 Excel。
8. 最终 DOCX、质检报告及递交清单。

原始文件、历史成果和人工修改保留，不因重新制作而覆盖或删除。

#### （二）收集并确认项目基础信息

优先从已有文件提取，不要求人工重复填报：

- 项目名称、项目编号、采购人、代理机构。
- 采购方式、标段名称、采购范围。
- 投标主体、联合体或代理关系。
- 投标截止时间、开标时间、递交地点和平台。
- 预算、最高限价、报价方式、税率要求。
- 交货期、交货地点、质保期、付款方式。
- 保证金金额、缴纳方式、账户、有效期及上传要求。
- 电子标工具、CA、加密、签章和解密要求。
- 原始采购清单、报价清单、技术附件及引用图纸。

#### （三）冻结本次输入

保存文件清单、版本、来源和指纹，明确当前采用的文件。

发现以下情况时分别处理：

| 情况 | 处理办法 |
|---|---|
| 缺少引用附件、BOM或报价清单 | 列为缺项；继续制作可确定内容，不编造具体行项 |
| 原文件与澄清冲突 | 核对效力及适用范围，记录被替代要求和当前要求 |
| 同一文件存在多个版本 | 确认当前有效版本，不凭上传时间直接判断 |
| 文件无法读取、扫描模糊或表格解析异常 | 使用页图、OCR或其他解析方式复核；无法确认的数值保持待核 |
| 历史项目日期已过 | 保留历史真实日期；未经确认不改成新的投标日期 |
| 人工指定缺项留空 | 在正式原位置留空，内部记录影响；不视为采购方豁免 |

### 三、招标文件研读与前期策划

#### （一）完整阅读范围

通读公告、投标人须知及前附表、资格条件、评标办法、供货要求、技术要求、合同、投标文件格式及全部附件。

不得只读技术参数或格式章节。扫描页、跨页续文、表格备注、脚注、签章要求和引用附件均纳入核查。

#### （二）输出《投标注意事项及招标文件解读》

至少包含：

1. 投标截止、开标、递交、答疑、保证金和解密等时间节点。
2. 投标主体、制造商或代理资格及适用范围。
3. 企业资质、产品证书、财务、业绩、人员、社保和信誉要求。
4. 评分条件、分档、证明材料和得分限制。
5. 无效、否决、不合格、实质性要求及特别提示。
6. 交货、质保、付款、验收、培训、售后和违约责任。
7. 保证金、履约担保、签字盖章、文件份数、密封或上传要求。
8. 招标文件内部冲突、缺失附件及无法明确判断的要求。

每项保留原文依据和来源位置，区分：

- 已有资料证明满足。
- 尚需补充证明。
- 需要商务或技术确认。
- 原文不适用。
- 已确认无法满足。

不能将“尚未找到材料”直接判断为“企业不具备”。

#### （三）形成四类清单

1. 不可缺失的资格与实质性条件。
2. 必须逐项回应的评审及评分条件。
3. 有真实依据可争取的优势和加分点。
4. 硬性禁忌及否决风险。

不存在量化评分的谈判、单一来源等项目，不虚构分值或“高分目录”。

#### （四）拟定澄清函

对缺失、歧义、冲突或可能无法满足的要求，逐项写明：

**条款及位置 → 原文内容 → 具体疑问 → 请求明确的问题。**

澄清函由人工审核批准后外发。未取得答复时，不能擅自把建议口径当作采购方已接受的条件。

#### （五）拟定投标目录

根据投标人须知、评标办法和投标文件格式建立唯一章节树：

- 强制章节、表式及顺序完整保留。
- 招标允许自拟的方案章节，按评分评价对象和高分特征组织。
- 每个评分点对应正文位置和证明位置。
- 不用固定通用目录替换本项目目录。
- 不为凑页数增加无关章节，也不因改技术表而缩减原有完整方案。

#### （六）形成产品型号与BOM初选清单

列明招标车型、数量、用途、核心配置、标准配置、选配件、配套设备及证明要求。

具体型号和BOM须有资料依据。招标未给出或尚未确认的内容留空，不从历史项目自动补入。

上述注意事项、澄清函、目录、型号及BOM清单，经人工复核后作为编制依据。

### 四、统一采用十步制作流程

| 步骤 | 主要工作 | 核心产物 |
|---|---|---|
| 1. 模板与要求分析 | 冻结输入，解析要求，生成、检查并冻结骨架及原文空表 | 章节树、要求矩阵、商务／技术骨架、槽位清单、技术原文清单、骨架锁 |
| 2. 基础字段填写 | 实填有来源的项目及企业字段 | 基础填写稿、字段清单、留空清单 |
| 3. 资格资料 | 匹配资格条件和实际证明 | 资格矩阵、资格结论、证明材料清单 |
| 4. 商务评分 | 按评审条件组织商务证据 | 商务评分矩阵、证书归位记录、商务填写稿 |
| 5. 承诺与声明 | 覆盖具体承诺及禁止项 | 承诺文件、覆盖检查、签署位置 |
| 6. 技术证据 | 确定车型、报告、配置及证据关系 | 报告级选材记录、技术证据矩阵 |
| 7. 技术响应 | 完成内部技术对标及技术、服务方案 | 内部对标 XLSX、技术与服务正文 |
| 8. 响应核对 | 复核资格、评分、条款、空表及跨章节一致性 | 四重质检、响应检查、缺项及留空复核 |
| 9. 组装与渲染 | 装配附件，更新目录页码，检查最终文件 | 完整 DOCX、附件嵌入清单、页码映射 |
| 10. 逐页终审 | 检查本次最终成品，复查历史问题 | 逐页记录、修订结果、交付决定 |

十步可以自动连续执行，但每步必须保存真实结果。不能仅记录“完成”，也不能跳过材料填充、附件装配或逐页检查。

### 五、先制作空白骨架，再按槽位填充

#### （一）骨架应包含的内容

根据招标原文生成：

- 封面、扉页及分册结构。
- 正式章节、子级目录、标题和表名。
- 招标固定文字、原表式和技术要求。
- 证书、证明材料名称及附件位置。
- 签字、盖章和日期位置。
- 已确定的分页、分节、横纵向和表格格式。

骨架阶段不得提前填入企业事实、历史方案、响应结论或虚构参数。

#### （二）验收并冻结骨架

检查：

1. 强制章节、表格和附件位置是否齐全。
2. 标题、顺序、编号和固定文字是否与招标一致。
3. 原表列数、列序、合并、备注和签章位是否正确。
4. 技术原文是否完整入表。
5. 字体、字号、位置、颜色及分页是否正确。
6. 是否出现孤立标题、空白续页或错误横纵向。

通过后冻结结构。冻结的是结构和分页规则，不是最终物理页数，正文填入后可以自然扩页。

#### （三）槽位检索与填写

每个字段、正文、表格、证书、证明附件和图片位置分配稳定槽位。

由槽位确定：

- 要找什么资料。
- 适用主体、客户、车型、年度及版本。
- 允许使用的资料类型。
- 对应招标和评分要求。
- 可否留空及重复使用。
- 原始来源、资料版本及填写记录。

不得先召回大量材料，再临时追加到文末或“其他资料”。

新增章节、表格或附件位置时，返回第1步调整骨架；不得在冻结结构外直接拼接。

### 六、资格审查与商务部分编制

#### （一）资格审查资料

按本项目实际要求编制，不默认每个项目均需以下全部资料：

1. 法定代表人身份证明、授权委托书及明确的授权有效期。
2. 营业执照、基本账户资料、一般纳税人证明。
3. 企业资质、体系认证及依法适用的许可。
4. 对应车型、子型号及部件范围的煤安、防爆等证书。
5. 财务报告、审计报告或银行资信证明。
6. 真实合同、发票、验收或用户证明。
7. 信誉查询及无重大违法等声明。
8. 项目人员、资格证书和符合期间要求的社保资料。

已知字段必须实填，不能因一个字段待定而将整张表留空。

#### （二）业绩处理

按招标要求核对业绩主体、产品、数量、金额、时间、关键页、验收、用户证明及联系人。

- 默认不自动选择历史业绩，不自动插入业绩证明。
- 未经人工选定时，业绩表保留原格式并留空。
- 经人工明确选定并要求回填后，按本项目条件填写并生成新版本。
- 排序优先遵守招标；未规定时，可按集团、相关性、数量、金额和时间组织。
- 资格业绩和评分业绩分别判断，不能把“不要求财务或一般业绩”理解成所有制造商供货证明均不需要。
- 未提供业绩时，如实记录资格或评分影响。

#### （三）证书处理

结合主体、类型、机构、等级、范围、型号、编号及换发关系判断，不仅按名称合并。

- 同一资格已有有效替代版本时，旧过期版本退出默认选材，历史原件和引用保留。
- 只有过期版本时，列入待更新资料。
- 日期不清或冲突时待核，不直接判定有效或过期。
- 尚未生效的新证书不提前替代有效旧证。
- 不同主体、车型、等级和适用范围分别保留。
- 按招标要求的有效日期核查，不能只判断制作当天。
- 未取得新原件时，不修改旧编号、日期或把旧扫描件描述成新证书；项目要求当前有效原件的，单独记录缺项。

#### （四）商务正文与证据归位

编制投标函、投标一览表、保证金材料、商务承诺及其他规定内容。

逐项覆盖交货、质保、付款、验收、培训、售后、担保和违约等要求，星号及实质性条款不能漏答。

商务响应核对矩阵与正式偏差表分开：

- 核对矩阵用于检查每项条款及对应正文。
- 正式商务、技术偏差表按既定留空政策保留原式。
- 不把内部分析表替换成招标正式表。
- 不凭空预填全部“无偏离”，也不遗漏未决条件。

公司简介、组织架构、服务网点、体系、荣誉、专利及软著按实际要求和评分位置归位，不重复堆放。

保证金凭证必须核对本项目、标段、付款主体、金额、收款账户和日期；缺少时留空，不拿其他项目凭证代替。

### 七、技术选型、技术对标与技术方案

#### （一）从招标原文形成技术要求表

优先读取原始 Word；只有 PDF 时，结合原文及页图形成等价原文清单。

遵守以下要求：

1. 按正文与表格交错出现的原始顺序读取。
2. 保留标题、章节、编号、星号、数值、单位、括号、备注及跨页续文。
3. 不重新编号，不按历史表行数决定本次行数。
4. “货物需求一览表”和“工作环境”各保留为一个完整响应点。
5. 技术参数按原编号和复合关系拆到可独立回答的条款。
6. 后续交付、服务、证明及履约要求继续覆盖，不在主要参数结束处停止。
7. 逐项与招标原文回验；漏项、多项、换序、改写或跨页缺句未解决前，不进入填答。

#### （二）车型与报告级选材

按以下顺序选择：

**采购类别和用途 → 同类车型 → 核心部件 → 其他参数 → 具体报告及配置。**

- 电机额定功率及型式、电池、电压平台、驱动和额定载荷优先于外形尺寸。
- 电机功率不能用更小值替代招标要求。
- 同类子型号中，电机满足但尺寸需调整的方案，可优先于尺寸满足但电机不足的方案。
- 满足要求的同类100kW配置，不因130kW更大而跨成另一车型。
- 选择后锁定具体型号、子型号、报告编号、版本、原件和整套配置。
- 不拼接不同报告的电机、尺寸、电池和其他参数。
- 长期维护的报告级参数总表作为第一参考，重要参数反查报告原页；没有的参数留空。
- 配件采购按具体配件、图号、接口及适配关系选材，不套用整车报告。

#### （三）正式 Word 与内部 Excel 分开

正式投标文件中的详细技术响应表：

- 保留原表式、标题、要求、列序及签章位。
- 投标人响应和偏离填写区按当前规则留空。
- 不加入子系统、部件、功能和标准答案等内部分析列。
- 其他技术方案、服务方案和证明附件仍完整编写、装配。

单独输出内部技术对标 Excel，固定排列为：

**子系统模块｜部件模块｜功能模块｜本项目相关车型的报告级标准答案列｜本次招标要求｜投标人响应｜偏离说明。**

同一工作簿可附“证据索引”和“核对记录”，不再另交独立技术偏离清单。

#### （四）十二类模块与多车型组织

前三栏沿用已确认的十二类子系统及原部件、功能映射：

高承载底盘子系统、整车、综合控制子系统、转向子系统、主动安全子系统、制动子系统、整车灭火子系统、永磁电驱动子系统、能量子系统、驾驶室子系统、底盘子系统、充换电子系统。

执行要求：

- 分类只用于定位和横向比较，不重排招标原文。
- 招标未要求的模块，其项目要求、响应及偏离保持空白，不增加配置。
- 招标已提出的条款，原要求、模块、同报告标准答案和响应必须同行对应。
- 找不到分类或标准值时留空并在核对记录说明，不猜配。
- 只保留本项目招标车型，不带入全部历史车型。
- 不同报告锁定的子型号分别成列，相近型号相邻，不合并数据。
- 招标合写多个车型，Excel也合写；招标分车型编写，Excel按原顺序分连续区域。
- 技术对标保持在同一工作表，不因车型拆成多个独立对标表。

#### （五）内部响应写法

完整保留要求中的对象、条件、数值、单位和时点，只转换应答语气：

- 不添加小标题或星号。
- 不简化成“完全响应”。
- 不照搬成熟答案中本项目未要求的配置或承诺。
- 不使用其他车型或其他报告值填补空缺。

正偏离按同一单元格组织：

完整应答正文

优于补充说明：简要说明实际优势。

证明材料详见：真实材料及交叉引用。

需适配调整项按同一单元格组织：

完整拟应答正文

补充说明：具体项目按本项目要求调整，待技术确认。

段落之间空一行，不另增业务行。内部最右栏按拟应标口径填写，工作簿显著注明其为内部审查结论；报告现值、拟配置及技术确认分开保留，不将拟配置冒充报告实测。

必交证书或报告缺失、适用范围不符等问题单独如实记录，不能用一般定制表达替代证明。

#### （六）技术与服务方案正文

按招标目录及评分评价对象，完整编写：

1. 产品配置、功能、技术特点及适用证明。
2. 技术指标及配置、标准符合性、先进性和可靠性。
3. 制造、生产机具、检测设备及质量控制。
4. 零部件、备品备件及供应保障。
5. 供货计划、运输、包装、仓储及交期保障。
6. 安装调试、到货验收及交接。
7. 现场风险、故障及应急处置。
8. 售后体系、响应流程、服务网点及备件保障。
9. 培训和质保期内外维修保养计划。

优先检索完整适用模块，再结合本项目改写，不直接复制旧方案或拼接零散切片。

源文档中适用的产品、网点、驻矿和用户评价等图片，实际嵌入对应章节。原尺寸可容纳时保持原尺寸；超出版心时等比调整，不裁切关键内容、不拉伸、不为凑页数放大。

提前交货、延长质保、增加配件等加分承诺，须经业务批准后采用。

### 九、文档排版、附件组装与最终文件

#### （一）格式优先顺序

本项目原表和明确格式 → 经确认客户模板 → 适用权威样例 → 手册默认格式。

无特殊要求时，沿用手册默认标准：

| 对象 | 默认标准 |
|---|---|
| 正文 | 宋体12磅，西文 Times New Roman，1.5倍行距 |
| 一至三级标题 | 宋体加粗16／14／12磅 |
| 普通表格 | 宋体10.5磅 |
| 密集技术表 | 宋体9磅，先保证可读性 |
| 页面 | A4纵向，上下2.5cm、左右2.7cm |
| 颜色 | 对外正文及标题默认黑色 |
| 目录 | 实际层级、点引导符、页码右对齐 |
| 落款 | 整块右对齐，保留签章空间 |

封面采用已确认模板。默认封面主标题60磅、项目字段14磅、投标人及日期16磅；招标原封面另有布局时遵原式，不强套默认。

招标要求价格、商务、技术分部扉页时，各自单独成页并居中；未要求时不额外增设。

#### （二）分页与附件

- 正式章、节、小节默认另起页，标题与首段、首表或首张材料同页。
- 无独立正文的父标题与首个子节衔接，避免只有标题的一页。
- 身份证明及证件尽量同页，不能以缩小到不可读为代价。
- 表格跨页重复表头，不产生多余空表续页。
- 正式留空表保留固定内容及必要行，不删除强制结构。
- 证书、报告和合同保持原貌，检查方向、比例、清晰度和完整性。
- 已选附件必须实际嵌入，不能只有名称和引用。
- 核对 DOCX 内部图片关系及原件对应关系。

#### （三）目录与文件交付

最终内容稳定后更新目录、页码和交叉引用，并反查实际页面。

默认交付 DOCX，不把内部渲染 PDF 当作用户要求的成果；必要渲染用于版式质检。

最终文件须实际读取或打开检查，不能只检查路径存在。不得用 JSON、损坏文件或空骨架冒充标书。

### 十、AI自查、人工审核与递交

#### （一）四重质检

1. **资格覆盖**：逐条检查主体、范围、日期、证明和成品位置。
2. **评分与响应覆盖**：逐条检查评分条件、正文、证明及最终页码。
3. **逻辑一致性**：核对名称、型号、数量、参数、金额、日期及各项承诺。
4. **错字与格式**：检查层级、表格、目录、分页、附件、签章和电子递交要求。

#### （二）专项自查

- 资格：证书有效性、适用范围、授权期限、查询时点、社保期间及原件清晰度。
- 商务：具体条件完整、保证金对应本项目、业绩选用正确、未决条件未被隐藏。
- 技术：要求无遗漏、报告配置一致、模块同行、参数有据、引用材料真实。
- 报价：计算及范围完整，无漏项、错税率或总分项不一致。
- 文本：无旧客户、旧项目、旧车型、历史价格、调试文字或未替换占位符。
- 签署：签字、公章、日期、骑缝章等按本项目要求逐处核对。

#### （三）逐页检查

对本次最终 DOCX 的全部页面，在可读尺度逐页查看并记录。

重点检查封面、目录、复杂表格、证书、图片、跨页衔接及文末。修改后重新渲染变化页和受分页影响的后续页面，不沿用旧版本检查结果。

不能把自动扫描、拼图或“已生成页图”当作逐页检查完成。

#### （四）人工审批与递交

人工分别确认资格、报价、车型、BOM、技术响应、服务承诺和签署材料。

形成递交清单，核查：

- 文件组成及顺序。
- 指定文件格式和附件。
- 签章、正副本、密封要求。
- 保证金到账及上传时点。
- CA、加密、上传、解密和截止时间。
- 当前有效澄清是否全部落实。

未实际测试平台上传、加密和解密时，不声称电子递交已验证。

### 十一、成果、状态与版本管理

#### （一）成果组成

按项目实际要求提供：

1. 完整可编辑投标 DOCX，按要求分册或合卷。
2. 本项目内部技术对标 XLSX。
3. 招标解读、四类清单、评分响应及四重质检结果。
4. 递交与待补事项。
5. 必要的报价文件，仅在用户要求且有批准数据时制作。

面向业务的解析、质检和待补内容可汇总为一份内部报告，不要求人工维护多份重复 DOCX。

不再单独输出旧式技术偏离清单；差异在内部对标工作簿内维护。

#### （二）状态区分

- 骨架完成：只代表结构冻结。
- 候选稿完成：正文和适用附件已装配，真实缺项明确，可供审核。
- 文件制作完成：文件、目录、版式及逐页检查完成，可能仍有业务事项。
- 可正式递交：要求、资格、证明、报价、签署、人工批准及递交条件全部满足。

缺资料留空不等于缺项已解决；AI文件生成不等于企业已批准。

#### （三）变更与恢复

- 澄清、表式或目录变化，从最早受影响步骤重跑。
- 企业资料变化，只更新受影响槽位及相关章节。
- 人工编辑保存新版本，重新生成不得静默覆盖。
- 下载、预览不产生新版本。
- 相同输入重复启动不重复建任务。
- 局部失败保留已成功成果，重试失败范围。
- 模型故障可代码兜底生成候选文件，但未完成的语义或视觉检查不得标为通过。

#### （一）项目归档

#### （二）资料模块维护

1. **公司通用资料**：常用企业字段、简介、组织架构和真实宣传材料。
2. **财务资料**：按企业及年度保存报告，提取营业额、利润等常用值并关联原表。
3. **人员资料**：人员档案、证书、简历和社保；历史任职不默认当前任职。
4. **证书资料**：续证、换发、到期及适用范围，保留历史追溯。
5. **业绩资料**：真实项目、合同、设备明细、发票、验收、用户证明及联系人。
6. **商务模板**：授权、保证金退还申请、声明、密封条和签章检查表。
7. **技术资料**：报告级参数、供货保障、产品及技术说明、完整图表和证明。
8. **售后模块**：备件、故障、回访、投诉、本地服务和应急保障。
9. **客户模板与权威模块**：完整章节、表格、响应和证据，注明适用主体、客户、产品、版本及来源。

资料按真实业务对象整理，不把文件名、章节名或文本切片直接当成业务记录。

报告级参数总表长期维护：相近型号相邻、不同报告分别保存、缺参数留空、更新保留来源和旧值。新增真实参数不能自动覆盖已批准项目。

#### （三）技能与操作手册保护

操作手册作为受保护指导书，只有明确提出修改要求时才能变更。

项目制作、局部修订、自动重试或新增资料，不构成修改手册的授权。确需更新时，保留原版、变更内容及影响范围，核对技能、模板、执行代码和检查规则一致后再启用。
