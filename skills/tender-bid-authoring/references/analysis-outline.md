# 解析成果与共享目录

## 评分原文、高分语句与完整子级目录

必须先找到本项目评标办法、评分表、评分细则和引用附件的完整原文，不能根据项目类型、历史目录或通用经验猜评分项。逐项区分资格门槛、响应性审查、否决条款和评分项；只有评分项进入评分目录设计。

每项评分记录：稳定评分ID、原名称、出现顺序、分值与最高分、基础得分条件、分档条件、高分/满分原句、评价对象、数量/期限/参数/证书/业绩/方案要求及原文位置。将高分原句拆成可验证的评价对象，但不改写事实边界；同一句包含多项独立证明维度时分别记录。

招标规定的一级章节、编号和顺序原样保留。在其下按评分表顺序把评价对象拟定为二级、三级目录。评分驱动节点直接使用高分/满分原句或不削弱评价维度的完整等义表达；不得把“设备整体设计成熟、合理，并进行横向对比”等要求压缩成“整体性能”，也不得删掉优于、完整齐全、具体措施和证明类型等得分特征。长句可规范标点和断行，但不写分值、“满分”或得分承诺。每个节点绑定评分项ID、高分条件、客户模板模块、权威库模块ID或`Fresh Generate`、本项目修改字段和证明材料。招标明确禁止增加目录层级时，不新增目录，但在既有章节正文位置建立同样映射。没有实质正文或证明去向的节点不得虚设。

客户模板库的候选标题只能辅助命名和召回，不能覆盖本项目评分原文。内部映射必须证明每个高分条件均有实际作答和材料去向；评分内容应放在对应价格、商务或技术章节，不得集中堆入“其他资料”。强制表格本身不增列、不换序、不改标题，补充评分正文只放在招标允许的表后或既有章节内。

### 权威库成对案例关系分析

参考权威库目录组织方式时，必须选择能够同时定位历史招标文件和对应正式投标文件的成对案例。逐项建立：`历史评分原文→历史投标目录节点→历史正文模块→历史证明材料`，判断目录标题是由评分项、强制格式还是企业补充内容产生。只有投标文件、没有对应招标文件的案例，只能作为版式或章节候选，不能证明评分目录组织规律。

当前项目先固定本项目评分项、顺序、评价对象和高分条件，再借鉴成对案例的层级深度、标题粒度及模块落位方式。不得复制历史项目的评分标题、章节号、车型或附件安排。多个成熟案例组织方式不同时，以本项目评分原文和强制格式为裁决依据，并在内部目录映射记录选用原因。

## 解析成果

**解析成果是必须产出的独立文件，不是应标文件。** 产出后与应标 DOCX 分目录存放，文件名标注「非递交件」；不并入应标卷、不纳入应标目录与页码、不随投标文件递交。目次页硬性规则与独立目录只约束应标卷，解析成果不适用。面向阅读的解析件不显示冗长来源、原文引文和内部证据台账，内部仍保留定位；它包含废标风险与评分对策等内部判断，一旦混入递交件即为实质损害，交付说明中须单独列明。

用户要求对齐云端“投标注意事项”时，只读核对现行字段及分组；无权限时声明尚未核对，使用此前确认结构需明确标为参考，不能声称现行接口如此。

已确认的阅读结构基准（本次任务可调整，不代表未经核对的云端现状）：

1. 项目重要信息：项目名称、开标时间、所投产品清单。
2. 项目基础信息：编号、标包、截止/解密/澄清时间、有效期、保证金金额方式到账时间、基本户、汇款备注、分册、递交渠道平台地址等。
3. 资格审查：按本项目招标文件明确规定的资格条件动态列项，栏目名称、数量和层级不固定。
4. 评标办法：方法、分值构成、响应性评审的具体条款、商务技术价格细则。
5. 废标风险：资格、电子操作、响应及强制承诺。

默认面向阅读的解析DOCX不显示冗长来源、原文引文和内部证据台账，内部仍保留定位。响应性评审必须列具体判定内容，不能只有“详见招标文件”“按规定执行”。

区分明确要求、明确不要求、未明确、尚未提取或冲突。分数逐项核对，不强行修正原文冲突。技术附件不能用局部矿名覆盖主体项目名称。

产品字段包括标包、包内序号、名称、参考型号、数量、单位、交货周期、地点。来自真实采购范围/采购表行，不把随车工具、零件、监控系统或重复数字变成独立车辆。技术附件有明确采购行可纳入；无法确定归属保留待确认，不能按文件名猜包静默过滤。参考型号不冒充已确认投标型号。

### 车型清单提取（制作流程步骤 4）

车型／型号清单是后续"依据车型检索权威库"的唯一输入，其来源只能是本次招标文件：采购范围、采购表行、技术附件的明确采购行。

- **本环节禁止调用知识库与权威库。** 车型基线不得来自历史案例、车型库或索引；先用招标文件确定投什么车，才谈得上按车型去检索。库中的车型不得反向决定本次投标车型。
- 参考型号保留在要求侧，实际投标型号用于答复；不因名称相近混用证据。
- 清单字段：标包、包内序号、名称、参考型号、数量、单位、交货周期、地点。随车工具、零件、监控系统与重复数字不成为独立车辆；无法确定归属的保留待确认，不按文件名猜包。
- 步骤1未锁定采购及投标配置前，不得按车型检索模块；资产完整性在步骤1内检查，证据召回按步骤3、4、6、7的业务任务开展。

### 资格审查动态列项

结合招标公告中的投标人资格、投标人须知、资格评审表及其引用正文，收集本次投标范围的明确资格条件，不套用固定七栏或其他固定分类清单。

- 优先保留原文的小标题、层级和顺序；没有标题时，按具体条件拟定简洁标题。栏目可多可少，不能为凑齐类别生成“未识别到要求”的空项。
- 同一条件重复出现时合并展示，保留主体、时间、数量、证明材料、提交时点及例外条件；不同标段的条件不得误合并。本次未投标段的专属条件不作为本标段门槛。
- 明确的禁止情形、联合体或代理商限制按原文实际列出；原文未涉及某类条件，不额外造出该栏目，更不能写成“无要求”。
- 区分资格门槛、评分加分、技术性能和履约阶段要求。评分业绩不能替代资格业绩，交货时提供的证书不能改写为投标时必须持有。
- 来源尚未查清或条款冲突时，在对应实际条目说明待核原因；不得将抽取失败伪装成招标文件没有要求。

上述动态列项仅用于解析成果，不改变招标文件明确规定的资格表单、章节编号或应标格式。

## 唯一章节树

先读本招标实际应标格式页，并区分说明性导航与明确要求投标人采用的格式。对确认属于投标格式的页面建立格式基线，逐项保存页面方向、纸张、页边距、标题、编号、父子层级、顺序、表格列结构、固定文字、注释、下划线、签章位、字体字号、行距、分页及目录收录范围。强制节点和版式原样保留；不得用权威库、评分目录或通用模板覆盖。价格/商务/技术按本项目规定分部；非报价任务保留要求的价格表空位，不复制历史价格。

内部节点保存稳定ID、父节点、强制性、标题、顺序、所属卷、模板来源、要求、评分项及条件、实际正文/材料、实际书签和页码。编号可能重复，稳定身份须包含文件、物理位置及适用范围，不能单凭条款号合并。

唯一章节树确认后立即生成商务、技术空白骨架DOCX，不先检索企业正文。每个节点、强制表单、技术要求行、证书/材料位置和签章位置建立稳定`slot_id`；全部招标要求通过要求覆盖矩阵映射到实际节点或槽位。骨架须按[空白骨架、槽位和冻结结构](skeleton-first.md)渲染、校验并冻结，目录清单或格式JSON不能替代真实Word。

招标提供DOCX格式时优先克隆；只有PDF时重建后以原页和页图逐项比对。骨架中只保留招标固定文字、章节目标题、表名、要求列及材料名称，不得写入企业值、历史项目内容或响应结论。需要新增节点或槽位时必须形成新骨架版本，不能在填充阶段临时追加。

按实际技术章节及其引用附件核对覆盖，不在车辆参数或安全条款结束处停止。证件、包装运输、供货服务、检验、质保和付款等后续要求也要对应实际回答或跨卷准确引用；若其他章节只有概述而未覆盖全部条件，仍需补充作答，不能仅写“按招标执行”。跨商务、技术内容保留原编号与适用范围，不遗漏或冲突，也不因此擅自扩展目录。

首版内部条款清单从招标正文及引用附件的第一项延续至最后一项，逐项记原位置、适用标包、性质、响应节点及成品位置。复合条款拆分核对条件，但保留原编号和原顺序；跨卷引用须指向实际写出的段落或表格行。交付前清点未分配、只有标题、仅复述要求或只写“按招标执行”的项，补成具体应答或列明实质障碍；不能因为第二节前半段已经成表，就默认后续章节已覆盖。

非强制参数汇总或响应表不额外展示招标原文印刷页码列，来源定位留内部；本项目强制表内的字段照常保留。此规则不删除真实证明文件页码、成品材料索引或目录页码。

覆盖核对以招标全文及引用附件为准，不沿用历史“若干条”作为完整性门槛。总则、参数明细、通用要求及后续履约内容保留实际去向；同一要求重复出现时保留原顺序并关联同一事实。本次正式商务、技术偏差表及详细技术响应表保留招标原结构但投标人填写区留空；详细技术拟响应由[横向技术对标工作簿](technical-excel-v138.md)单独完成，不另出技术偏离清单。

同时检查表头、项目名称后缀及单元格中的来源页数，不只删除独立页码列。用户要求集中定位时，证明页码放材料索引，响应表保留真实文件名；招标原表与补充响应表分别检查，不能把通用格式当作原表一致性依据。

评分组织原则：先提取评分项名称、评价对象和高分条件。强制父章节保留招标原名，其下评分作答标题直接突出高分特征，不因标题较长而退化为评分项简称。本次业绩不提交，业绩资格和评分影响单列记录，不虚设业绩证明节点；其他商务评分项落入对应章节。体系认证用于评分时放评分材料章节，否则放其他商务资料。技术评分项按招标允许的技术父章节展开。比较性评分没有客观阈值时不虚构满分参数。

每个评分项映射到实际正文或材料，可一对多、多对一；无合适位置保留原因。不得为映射率统一塞进“其他资料”，也不能只加空标题。强制父章节下的基本情况、财务、业绩应是子级，不再重复追加一级章节。

技术部分首先原样保留招标规定的全部章节、标题、编号、层级和顺序。招标目录或格式固定时，将“整体技术性能响应、运营可靠性、质量保障、技术支持、操作维修与成本、质保及售前售后服务”等评审对象写入其指定章节的正文，不得为显性展示而新增、改名或下沉目录节点；必要定位使用不改变原结构的正文引导或材料索引。只有招标未规定子级格式且允许扩展时，才按评分顺序建立次级节点。评分作答必须有实质内容，但“有内容”不构成改变强制目录的理由。

技术评分涉及企业成熟模块时，在内部建立`评分标题—强制父章节—权威库成熟完整章节—本项目修改字段—实际作答—证明位置`映射。强制父章节决定落位，评分标题决定作答边界；以评分标题或同义表达检索历史原卷，选取同客户、同集团、同车型/业务中正式使用过的完整章节，将其既有子标题、正文、表格、图片和材料编排整体作为基线，再按本项目要求替换、删减和补充。不得反过来让模型先自拟章节逻辑，再把历史内容压缩成临时概述。仅有目录节点或临时概述不算已采用模块；模块不适用于本次车型或承诺范围时只采用可核实部分，不为追求评分覆盖扩写无依据内容。

本次正式商务、技术偏差表业务确认不填写：原表题名、说明、表头、列结构、原固定行和签章位保留，投标人填写区留空。技术详细响应及内部偏离记录继续逐条保留真实判断，不从中回填正式表。

精简前逐行统计真实状态，不因表很长就认定都是正常条款。证据缺口、材料未完备与正负偏离分别保留；经用户确认可在同章节采用紧凑说明表，但须保留每项原编号、具体限制和原响应定位，不能为减少页数将缺口隐藏或改判为满足。

紧凑说明表只是布局转换：建立原表行与新表行的对应关系，逐字段核对原要求、现有回答、偏离或缺口状态、具体说明、证据引用及响应位置；原表已有的信息全部保留，不以数量相等替代内容核对。新表可另加连续展示序号，但不得替换原编号、合并不同条款或改变原有顺序与结论；换列、换行不应丢失限定语。

## 目录输出

### 证明材料的目录收录层级

权威库成熟标书中的材料标题不是当前项目的默认目录白名单。先判断该标题在对应历史招标中属于强制格式、独立评分/资格事项、关键材料类别，还是仅为原件前导语；只有前三类在本项目存在同等依据时才可进入当前目录。

默认层级为：`分部→招标强制章节→评分/资格事项→必要的关键材料类别`。具体原件文件名、单张证书或报告、查询截图、身份证正反面、合同/发票内页及连续附件页，统一在正文材料索引记录名称、主体、型号、适用项和最终页码，不逐份进入主目录。下列情况可继续展开：

- 招标明确要求在目录逐份列示；
- 每份材料本身是独立计分单元，如逐项计分的业绩、荣誉或认证；
- 每类材料对应不同资格条件、否决风险或独立评审对象，评委需要直接定位；
- 用户已明确授权该项目展开，且正文、附件和真实页码均已闭合。

不得仅因材料已附入、文件数量多、历史目录曾列出或Word段落使用Heading样式，就把它升为目录节点。材料分类标题进入目录后，其下原件仍由材料索引承载；没有实际原件的类别不得生成空目录项，非评分证书不得挂在评分标题下冒充得分材料。

价格及商务卷、技术卷及完整投标文件的目录必须覆盖完整项目章节树，置于封面之后、首个分部扉页之前；只有招标明确限定“本卷目录”时才缩减为本卷章节。分别交付的分卷共用同一标题、编号和层级清单，价格、商务、技术页码按卷别真实标注。评分型节点按上述高分特征命名，并分别落入其业务归属章节。

商务、技术及独立目录由同一章节树及实际输出生成。除招标明确限制外，各正式分卷目录均列完整项目章节；页码按所属分卷的最终页码标注，不伪造跨卷连续页码。解析成果必须产出为独立文件但不属于应标正文，不列入正式目录，也不占用应标卷页码。

子级编号必须继承当前父级编号，父级调整后旧子级编号不得残留。子级名称必须与正文标题及实际材料一致：评分要求可决定应设置的节点，但未附入的评分材料不得用其他证书、报告或截图改名冒充。

价格、商务、技术等分部节点在章节树中标记为分部扉页节点。除招标另有明确格式外，分部节点独占一页、标题居中，后续正文从下一页开始；目录收录分部节点并使用实际扉页页码。卷封面与分部扉页分别建节点，不能因标题相近静默删除，也不能在招标未要求时重复生成同义封面。

**多级卷内目次是默认交付要求。** 商务卷、技术卷及完整投标文件默认在封面之后、首个强制节之前设置多级目次，不再以页数阈值决定是否生成。招标明确禁止增设目录、要求固定上传结构或规定其他目录格式时，服从招标文件并记录采用依据；不得为了通用规则破坏强制格式。收录范围、目录域与页码口径见 SKILL.md「目录与页码」。

目录收录白名单为“本项目内置投标目录＋本次明确授权扩展项”，保留原标题、编号、顺序和收录深度。不要自动收录全部Word标题、表单名称、证书名称或材料说明。参考表单名称可按正文格式保留；“不适用”等答复放正文，不改写强制目录标题。

本次业务确认目录示例要求展开报价分表、年度财务报告、资格/信誉材料或其他商务资料时，逐项建立真实正文节点并同步收录。旧项目“仅扩展业绩”的决定不能限制新确认的展开范围；也不能把本次示例的每个子标题固化到所有项目。示例页码不复制，编号异常与原招标核对，不机械继承错误。

用户后续明确要求列出业绩时，在原业绩章节下按实际项数连续列出“业绩1：买方/项目简称”等条目，目录、正文、表格和证明材料一一对应；不得写死为4项，也不得把第一项的标题误写成统领全部材料的标题。本次已确认业绩留空，不适用该展开规则。无原文或用户依据时，不额外增加“类似供货业绩汇总”“业绩合同发票及查验材料”等中间层。用户指定扩展项可保留，不因此恢复其他已取消的扩展子级。

非强制目录版式参考适用历史卷的层级缩进、点引导线、右对齐页码，不默认用网格表。强制目录仍服从原招标。

需要可更新目录时，目录域按已确认节点或专属样式限定收录，不能直接自动包含所有Heading。保存核对后的显示页码，回填材料索引后再确认分页；另一卷未改时保留其有效页码。参考卷的未更新目录不是可复制的页码依据。

### 子级编号与层级

先按共享章节树确定父子关系，再分配编号；不能把“补上（1）”理解为所有深度统一加同一种前缀。原招标的强制编号优先保留，新增子级沿用该位置已确认的层级规则。无强制规定且用户采用此口径时，使用“一、→（一）→1.→（1）→①”；这不是覆盖所有项目原编号的默认重编号命令。

- 同一语义层级使用一致编号形式，进入新父节点后重新起号；不能同级混用“（一）”与“（1）”，或相邻父子级重复使用“（1）”。例如“（一）基本情况表”下用“1. 营业执照”，“1. 网站查询结果”下用“（1）具体查询材料”。
- 招标章节编号、附件编号、表号和用户明确保留的“业绩1：……”属于不同含义，不把附件号当成章节层级，也不重复叠加业绩序号。保留这些标识与实际材料的对应关系。
- 正文标题、卷内目录、独立目录从同一份节点编号生成；核对实际父节点、标题样式/大纲层级、缩进、同级字号和显示前缀，不只按标题文字批量替换。编号修订不授权新增目录项或改变正文事实。

交付前按白名单检查全部目录条目，而非只检查业绩区域。业绩扩展不授权新增证书、保函参考格式、材料汇总或评分子标题；多出的目录项取消，必要正文保留。需显示业绩父级时只保留必要父级，不连带扩展其他资格子级。

同级字号、真实页码及修订后的联动范围依[文档制作与检查](document-production.md)执行；独立目录不得沿用旧合卷页码。
