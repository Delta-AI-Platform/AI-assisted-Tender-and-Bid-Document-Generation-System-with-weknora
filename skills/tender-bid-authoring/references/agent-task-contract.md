# Agent阶段任务契约

开放性任务必须使用结构化任务包，不得只给模型一句“分析、生成或优化”。任务包用于评分理解、模块匹配、客户化改写、技术响应、商务适用性判断和逐页视觉检查。

## 必填输入

1. `task_id`、项目ID、阶段名称和本次允许修改的产物。
2. **输入原文**：招标评分原文、技术/商务要求原文、格式原页、业务确认、项目事实、候选历史模块和证明材料正文或页图；每项附文件、页码/条款ID及哈希。
3. **Agent职责**：只定义本阶段承担的理解、匹配、改写或视觉判断，不授权修改Rulebase锁定事实、原格式、原要求列和其他卷。
4. **阶段任务要求**：目标、输入范围、输出结构、禁止事项、完成标准、与前后步骤的接口和无法判断时允许的状态。
5. **Rulebase约束**：格式基线版本、事实台账版本、允许目录父节点、锁定字段/列、可用状态枚举和必须通过的回验规则。
6. **骨架约束**：当前`skeleton_id`、允许读写的`slot_id`、对应章节和要求、禁止改变的结构。步骤1的Agent可以解释原文并提出骨架节点，但骨架通过Rulebase和渲染门禁后，后续Agent不得新增标题、表格、行、列或附件位置。

## 结构化输出

模型至少返回：

- 原文位置或稳定ID；
- 对原文的理解结果；
- 采用的历史模块ID和来源；
- 适配理由及复用等级；
- 替换、删除和新增字段；
- 使用的企业事实与证明材料；
- 建议目录节点及正文位置；
- 实际目标`slot_id`及该槽位的资料适用性；
- 输出正文或视觉问题定位；
- 状态、风险、缺口及不能判断的原因。

自由文本只能作为上述字段中的正文内容，不能替代结构化结果。引用历史内容时必须返回来源和本项目修改项；视觉检查必须返回页码、页面类型、问题位置、观察结论及建议修复。

Agent结果状态只允许：

- `pass`：本阶段要求的语义或视觉工作已经实际完成；
- `candidate`：模型不可用、只完成代码兜底或仍有未闭合判断；必须同时提供`execution_mode=code_fallback|agent_partial|manual_pending`和非空`open_items`；
- `blocked`：输入损坏、必需原文缺失或结果不可安全使用，本阶段不能继续。

`candidate`允许状态机继续后续确定性制作，防止模型故障阻断已有成果；它不是审核通过。交付门禁要求所有阶段最终为`passed`，不能把`candidate`自动改写成`pass`。

## 执行闭环

统一执行顺序：`Rulebase固定招标输入 → Agent理解章节与槽位 → Rulebase生成/校验空白骨架并冻结 → Agent按槽位理解/生成 → Rulebase槽位及结构回验 → Agent视觉/语义复核（需要时）`。

Rulebase失败项不得被Agent改写为通过。Agent不能判断时使用任务包允许的`unresolved`或具体缺口状态，不臆造事实；Rulebase通过只证明已编码的不变量，不代表内容质量、证据适用性或正式递交条件已经成立。
