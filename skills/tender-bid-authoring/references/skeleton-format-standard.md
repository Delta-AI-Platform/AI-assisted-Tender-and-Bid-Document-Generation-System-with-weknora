# 骨架文档格式标准与模板

本标准用于招标文件没有给出完整字体、字号、颜色或位置规则时，为第1步空白骨架提供确定性默认值。格式采用四级优先顺序：

1. 本项目招标文件明确规定及原表式；
2. 与本项目客户匹配、经确认可复用的成熟模板；
3. 权威库同客户、同车型或同类项目的真实投标文件；
4. `assets/skeleton-format-standard.json` 中的统一默认格式。

低优先级不得覆盖高优先级。证书、合同、检测报告等原件页保持原貌，不套用正文格式。历史文件中的项目值、签章、价格和异常配色不得随版式一起复用。

## 权威样例依据

默认值依据权威库真实投标文件和已验证 H112 v129 商务、技术卷统计确定：成熟文件的普通正文以宋体12磅为主；一级、二级、三级标题稳定落在16、14、12磅；普通表格以10.5磅为主，密集技术表以9磅为主；封面主标题为60磅，项目字段为14磅，投标人和日期为16磅。权威原件及成熟卷的对外标题和正文均以黑色为主。

历史生成器曾出现蓝色标题或青色表头文字。这些颜色不是权威库通行格式，默认模板不继承；只有招标原表或经确认客户模板明确要求时才保留颜色。

## 页面和分节

- 默认A4纵向，上下页边距2.5厘米，左右页边距2.7厘米。
- 招标原表较宽时设置独立横向分节。密集横表默认边距1.27厘米；表格结束后必须回到纵向分节。
- 页面方向、页边距和分节必须来自招标原表或骨架规格，不能为减少页数擅自改为横向。
- 每个正式章、节、小节按项目规则另起页；标题设置与下一个对象同页。正文增长只允许自然扩页。
- 目录使用正文真实标题和最终页码，页码右对齐并使用点引导符；不靠手工空格排版。

## 颜色规则

- 对外骨架默认文字颜色统一为`#000000`。
- 表头可使用`#F2F2F2`浅灰底，但文字仍为黑色。
- 不使用蓝色主题标题、青色响应文字、渐变、阴影或装饰性色块。
- 招标原表、客户确认模板、既有标识或强制偏差颜色是例外，必须记录例外来源并在骨架锁中保存。
- 证书、合同和报告原页中的颜色不属于正文颜色检查范围。

## 模板和执行文件

- 默认格式参数：`assets/skeleton-format-standard.json`。
- 程序继承用无正文样式母版：`assets/skeleton-style-template.docx`。打开时显示空白属于正常状态。
- 供业务查看的可见商务骨架：`assets/skeleton-business-reference-template.docx`。
- 供业务查看的可见横版技术骨架：`assets/skeleton-technical-reference-template.docx`。
- 默认封面不显示“第一部分、第二部分、商务文件、技术文件”等额外分册文字；只有招标文件原封面或经确认客户模板明确要求时才保留。
- `scripts/skeleton_tools.py build` 默认自动应用上述模板和参数；项目可在规格中用`style_profile`或`style_template`明确替换。
- 生成目录会保存一份`skeleton_style_profile.json`，并在骨架清单及锁文件中登记`profile_id`和SHA256，避免模板后来变化而影响历史项目。
- `validate`和Rulebase的`docx_skeleton_format_standard`检查字体、字号、颜色和必需样式；`freeze`把`styles.xml`、主题、字体表、分节及模板哈希一起锁定。

## 骨架验收

1. 先比较招标格式章和原表，记录所有项目级例外。
2. 检查封面三区位置、字号和对齐，不接受左上堆叠或连续空段定位。
3. 检查同级标题字体、字号、颜色一致，且没有Word默认蓝色主题残留。
4. 检查普通表与技术表的字号、表头重复、列宽、合并、横纵向和分页。
5. Office渲染后逐页检查标题孤行、表格截断、字体替代和非预期颜色。
6. 校验通过后冻结骨架；填充阶段不得修改样式、主题、分节或非槽位位置。
