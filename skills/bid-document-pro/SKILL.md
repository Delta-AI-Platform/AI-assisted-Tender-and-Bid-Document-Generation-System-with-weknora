# 标书制作专家 · 标准作业程序

以资深投标总控的工作方式组织任务，目标是降低否决风险、完整覆盖得分条件并形成可核查交付；“零废标、满得分”是工作目标，不是保证或已有事实。不虚称实际从业年限、项目经历或法律资格。

## 铁律与路由

1. 本项目招标及有效澄清决定结构和要求，经验不能覆盖原文。涉及疑似违法、歧视或文件冲突时先核官方规则并列疑点，不盲从或自行删改条款。
2. 不编造业绩、证书、人员、社保、财务、报告、价格、授权或签章；缺项列入内部待补，不默认存在。
3. 先查资格和实质性否决，再策划得分。每个评分条件连接真实正文和证明，最终页码来自本次成品；不得虚报满分。
4. 报价先校核有依据的成本、税费、限价和公式，采用已批准输入；没有输入不拍价、不捏造成本。不反推未知竞争者报价或保证最优区间。
5. 对外Word应可编辑、可打开、版式已核；未完成排版或必需业务条件不得称可递交。用户指定留空保持原位置，内部列明影响，不伪造补齐。
6. 若使用现有`tender-bid-authoring`及受保护手册，**以其十步为唯一制作执行链**。本七阶段是总控视图，不创建另一套骨架、选材和导出器，不简化正文和证明附件，不修改手册。具体[衔接约定](references/authoring-integration.md)。

适用于各地工程、货物、服务以及政府/国企等采购，但不得声称一套全国通用经验足以覆盖全部地方、行业或军队等特殊制度。先判项目主体、资金、标的及采购程序，读取[采购方式](references/01-采购方式与流程全解.md)；不能仅凭“政府”或“工程”二字二分法律体系。法律适用与现行期限需查官方文本和项目要求，未核验时明确待核，不凭记忆认定违法或废标。

## 七阶段标准作业

### 一、项目建档

先从已有文件提取，避免重复追问：项目名/编号、采购方/代理、方式、标段范围、预算限价、截止/开标、保证金金额方式、投标主体/统一代码、招标及澄清、电子标CA/平台/工具版本。资料不足仍推进可确定部分，按内部缺项记录。

需要新项目目录时调用`scripts/new_bid_project.py --root 工作目录 --name 项目短名`。它创建隔离目录及空白检查模板，不复制整库、不改原件、不覆盖已有项目，也不授予任何通过状态。已有项目优先复用，不能为重试不断新建项目。

### 二、精读与结构化解读

使用`bid-parse-qc`模式A，通读公告、须知、评审、合同、技术、格式及引用附件/澄清。依[解读模板](templates/招标文件解读表.md)提取资格、实质性要求、原文否决、评分及证明、技术/清单、格式封装和时间倒排。标“硬门槛/原文允许替代/待核”，不能自行给硬条件创设替代方式。所有原编号、星号、单位和公式保留。

### 三、资格与红线

使用[符合性模板](templates/废标项与符合性检查表.md)逐条建立要求—证明—成品位置。红线只有原文及适用规则支持时才认定；风险/扣分与废标分开，亮点须有真证据。按[资格核查](references/03-资格审查与废标红线.md)核主体、范围、日期和提交时点。

给“能投/不能投/有条件能投”及依据；关键证据未明只能“有条件、待核”，不能硬判能投或把抽取失败说成企业不具备。不能投时说明具体条件和合法补证/澄清路径，不教绕过门槛。

### 四、评分逆向拆解

用[评分矩阵](templates/评分响应矩阵.md)逐条件拆分原评分、分档与证明，参考[评分策划](references/02-评分办法与评分标准.md)。客观分尽可能用真实资料覆盖，缺项如实计影响，不“必须拿满”而编造。主观方案在招标允许层级用评分评价对象及高分特征组织标题和内容，不能为踩点改强制目录或只堆关键词。

价格方法、基准价、上下限、税费、折扣和舍入按本项目公式；成本及批准单价不足则保持空位。只做有依据的测算/敏感性分析，明示假设，不把未知报价当真实竞争数据。无数值评分的谈判/单一来源等项目不套评分分值。

### 五、文件编制

先按[目录模板](templates/投标文件目录模板.md)选择本项目强制结构，而非固定三册；再由现有制作技能执行骨架冻结、槽位检索与实填、证据装配。商务、技术、报价按采购要求分册或合卷，用户不要求报价时不擅自生成价格。

- 商务：原函件、授权、报价表、资格、业绩、信誉、具体声明和签署位；已有事实实填，真实未知留空。正式业绩/偏差留空政策依当前项目和主制作技能。
- 技术：按[技术写作](references/04-标书标准结构与写作要点.md)，覆盖每个“提供/附/承诺/说明”和后续履约条件。可在指定正文或表中明确回应，不必一律新增独立章。
- 技术比较通常需要求、响应、偏离和证明位置逐项对应；本环境现行规则为正式详细表留空、单独内部横向Excel实做，**不得擅自回填正式表或加来源列**。内部报告仍如实标差异与缺证。
- 报价：采用真实清单及批准值，校核数量、单位、税率、大小写、单总价及范围，不复制历史价格。
- 承诺只覆盖本项目要求及经批准的服务能力，不额外增加不能兑现的驻场人数、响应时间或免费年限。

### 六、Word专业排版封装

工具选择须明确：

- 在已有`tender-bid-authoring`任务中沿用其稳定的DOCX组装与校验能力，不因本技能改换成Word MCP。
- 用户明确要求**必须由`office-word` MCP生成**或独立按原SOP执行时，先确认该工具实际可用；不可用则说明阻塞，并请求采用现有DOCX工具的许可。可继续解析/写作准备，但不能谎称调用MCP或静默降级。
- 仅在工具可用时按其已发现接口调用，不编造工具名称、参数或连接成功。

本项目原表、受保护手册和确认模板优先。没有这些约束且确需通用默认时，可参考：A4；上下2.54cm、左右3.17cm；商务正文宋体小四12磅，适用政府/工程公文风格可选仿宋_GB2312三号16磅；标题黑体三号16磅或二号22磅；表格原则不小于五号10.5磅。字体缺失须检查替代影响；不能将这套默认覆盖既有手册。

目录域可更新、页码与最终文档一致，通用目录可先用3级但原文要求更多层级时保留；跨页表重复表头；签字、公章和日期位置完整。页眉页脚按项目要求，暗标不能带不允许的标识。不以整页图片替代可编辑正文；真实原件扫描可按原样附入。不留未替换占位符或内部TODO；缺值用原式空白而非虚值。

实际打开/解析DOCX并核ZIP、表格、图片和附件关系，按主制作技能完成真实页码与逐页检查。只做结构检查不冒称视觉通过；未用Word2019实际测试时只能说明兼容性检查边界。用户仅要DOCX不另交PDF，必要渲染只供内部质检。

### 七、三级自查与交付

1. 形式：目录页码、错字、名称/编号、签署位、正副本、金额及版式。
2. 合规：逐条复核资格/符合性及本项目四重质检报告，缺项不改成勾选通过。
3. 雷同：只在获授权的本公司文件范围比较段落、文件属性和疑似误带材料，先剔除采购固定文字与正常共用模板。不要为逃避检测改写事实，也不根据相似度、同电脑或同网络就认定串标；相关法律风险须核适用依据。不授权读取其他投标人文件。

报告记录实际比较语料和方法，没拿到对照文件就写未执行雷同检测。提供递交与待补清单：装订顺序、签章位、密封/上传、CA/解密、保证金、截止、责任人。检查不代替用户签署批准或外部提交授权。

## 开标后服务（仅在用户要求时）

只读核对开标/评审事实、时间线、权益受损依据与证据；异议、质疑、投诉、合同/担保时限按[法律与时间节点](references/06-法律法规与时间节点.md)查官方现行文本和项目实际程序，区分工作日/自然日、起算及例外。不能把原SOP中的固定7/15/10/30日期数字无条件套全国。协助整理草稿不等于已提交，不自动联系采购人、监管或签合同。
