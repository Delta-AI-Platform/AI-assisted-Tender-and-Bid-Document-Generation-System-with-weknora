# 标书解析与四重质检

无需另购解析服务或申请外部API Key；使用当前环境的文件读取与模型判断。“零额外依赖”不表示任意环境天然具备PDF/OCR/Office，也不承诺模型免费。先检查实际能力，缺失时说明边界，不擅自安装或上传商务资料。

## 模式与读取

- **A 招标解析**：解析招标、提取资格和评分、判断参与条件或废标红线时，读取[四类清单模板](references/parse-checklist.md)。
- **B 四重质检**：审查投标/响应文件、漏答或冲突时，先取得当前有效招标基线与待检成品，再读取[四重质检模板](references/qc-four-pass.md)。旧解析须核对输入哈希和澄清后才能沿用。
- 只有公告片段时可回答已知及通用注意点，但不得声称完成全文解析。关键词辅助选择，不因提及“投标”就启动无关完整任务。
- 完整制作中按[衔接契约](references/authoring-integration.md)调用，不把制作任务缩减成只交报告。

冻结项目、标段、主体、招标/附件/澄清、待检成品和SHA-256。澄清的替换或补充关系看正文，不按上传时间猜测。读取全文及引用附件，保留原编号、星号、单位、公式、表格与页序；跨页续文先衔接，原文和解释分开。

优先使用可完整读取文件的现有能力。容量不足时改本地提取并分段读，不照搬WorkBuddy的256KB限制和专用Python路径。`scripts/extract_source.py`可提取带来源位置的UTF-8文本/JSON：DOCX用标准库；PDF用现有PyMuPDF或pypdf，均不可用则报缺依赖，不自动安装。`.doc`用可用办公工具转新副本或请求可读版本，不能改扩展名冒充转换。PDF扫描页、表格合并、图章遮字及符号须核对原页；无文本页是OCR待补，不是“无要求”。物理页与印刷页区分记录。

## A：四类硬交付

先识别项目概况、采购范围、资格、技术参数、评分、格式签章和时间节点，再分类：

| 清单 | 判断与输出 |
|---|---|
| 不可缺失资质/资格 | 主体、范围、等级、日期、证明方式及原文否决条件；我方满足须有证据 |
| 必答评分项 | 原条件、客观/主观、分值/分档/公式、证明及建议/实际章节；漏分不自动等于废标 |
| 加分亮点项 | 原文允许的高分条件、真实可用优势及材料；不得编造配置或满分保证 |
| 硬性禁忌条款 | 禁止、实质性响应、暗标、签章及电子递交红线，保留触发条件、例外和原文后果 |

资格、响应性、评分和履约条件分别管理。同一要求可关联多类但用稳定`requirement_id`关联，不重复计分；编号不能作为唯一身份。没有数值评分表时说明原文依据，不套用历史分值；未读完不能写“未规定”。末附有依据的参与建议及未决条件。

项目已有`<前缀>_内部缺项与来源.json`的`hard_gaps`时，每条必须映射到清单的现状/风险列。其他资格矩阵、交付结论按实际字段核对，不预设都有该字段。暂不能分类的缺项单列待核及原因，不丢弃；“已解决”须以本次证据和成品重新确认。

## B：四重执行

1. **资格全覆盖**：逐条连接正文、证明、主体/范围/日期及实际嵌入位置。标题、资料库命中或原件路径不等于已附。
2. **评分逐项响应**：逐条件核查实际章节/段落、表格和附件，复合条件全部覆盖；只有同名标题或“完全响应”不算实质作答，不承诺评委给分。
3. **逻辑冲突**：核项目编号、标段、主体、金额税率、数量单位、型号报告、日期期限、人员及承诺与证明；冲突列各位置和值，不擅自统一数字。
4. **错字格式**：文字层级、固定表式、目录页码、字体行距、图片附件及签署位；文本/包内检查与逐页视觉分别记录，无最终渲染不能声称视觉通过。

每行输出`检查项｜结果｜招标依据位置｜成品位置｜实际发现｜修改建议`。末附合规性/完整性/严谨性三维结论及P0/P1/P2修改清单，未执行/阻塞明确列出。

## 判断边界

- 使用✅达标、⚠️待补/待核、❌已证实不满足/高危。是否废标单列原文依据，不把所有缺证、扣分或格式瑕疵直接等同废标。
- 技术比较写无偏离/正偏离/负偏离；证据不足写待核，非技术项可不适用。缺证明与技术负偏离分开；内部拟应答不代表报告实测，已证实差异不得在审查报告隐瞒。
- 不编造资质、业绩、人员、奖项、参数、价格和签章。不同主体、子型号、等级和范围不混用；不按文件名判断证书新旧。
- 用户指定留空不等于采购方豁免。保留空位并在内部写风险，不擅自回填正式表或授予达标。
- 只有原文和证据不够判断时保持待核；“没找到证明”不是企业一定不具备。涉及现行法律或时限须查官方版本和适用条件，无法核验则标未验证，不凭记忆出法律结论。
- 敏感报价成本仅在授权本地任务使用，密钥不输出；不自动引导用户上传到商业服务。

## 落盘和衔接

按用户指定项目目录保存；未指定且主工作区存在时用`交付文件/<项目短名>_<YYYYMMDD>/内部审查_非递交件/`，不覆盖旧版本。

- `<前缀>_招标解析报告_<YYYYMMDD>.md`与同名`.html`。
- `<前缀>_四重质检报告_<YYYYMMDD>.md`与同名`.html`。

Markdown采用结构化表格；`scripts/render_report.py`生成UTF-8、内联CSS、浅色HTML，无外部资源。报告含风险与缺项，不进入递交DOCX、正式目录或页码。HTML只预览报告，不等于Office文档渲染和视觉审核。

说明用途、实际检查范围及未决项，可建议补齐后复审。用户要求成品时衔接`bid-document-pro`或`tender-bid-authoring`；不能以报告替代应填正文、证明附件、真实DOCX、内部技术对标及终审。不因用户只要解析就擅自制作、修订或提交投标文件。
