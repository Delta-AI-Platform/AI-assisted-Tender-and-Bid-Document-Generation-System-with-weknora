# 数据结构

所有中间文件都是 UTF-8 JSON，`ensure_ascii=False`。文件名可改，字段名不要改——脚本按字段名取值。

---

## 1 `requirements.json` — 招标要求（Step 1）

```json
{
  "source": "招标文件 -技术部分.pdf",
  "sections": [
    {
      "code": "5.1.1", "title": "整车基本参数", "kind": "table",
      "rows": [
        {"no": "1", "cells": ["参考型号", "WLR-5（自动挡）", ""]},
        {"no": "2", "cells": ["乘坐人数（人）", "5（含司机）", ""]}
      ]
    },
    {
      "code": "6.2.5", "title": "电源和电源管理系统", "kind": "para",
      "clauses": [
        {"no": "",     "text": "防爆锂离子蓄电池电源应满足 MT/T 1200-2023……"},
        {"no": "（1）", "text": "电池模组应采用激光焊接工艺。"}
      ]
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `code` | 招标章节号，原样（`5.1.1` / `6.2.5` / `7` / `9`） |
| `kind` | `table` 参数表 / `para` 条款段落 |
| `rows[].no` | 原文行号；拆分行用 `12-1`，共享父行号 |
| `rows[].cells` | 原文各列，顺序不变（名称/指标/备注…） |
| `clauses[].no` | 原文编号：`（1）` / `1、` / `""`（原文无号） |
| `clauses[].text` | 原文正文，**不含编号**、不含页眉页脚 |

`5` `5.1` `6` `6.2` 这类纯分组标题节：可选保留，出表时跳过（`skip: true` 亦可）。

## 2 `module_dict.json` — 模块字典（Step 2）

```json
{
  "subsystems": ["动力与行驶系统", "制动系统"],
  "parts":  [{"sub": "动力与行驶系统", "part": "整车基本参数", "code": "M01"}],
  "functions": [{"part": "整车基本参数", "func": "续航里程（km）", "code": "F001"}],
  "items": [
    {"id": "T-5.1.1-15", "kind": "table", "code": "5.1.1", "no": "15",
     "model": "矿用防爆指挥车 WLR-5", "sub": "动力与行驶系统",
     "part": "整车基本参数", "func": "续航里程（km）",
     "req": "续航里程（km）：≥120"}
  ]
}
```

`kind`、`model`、`func`、`req` 为匹配与出表必需；`sub`/`part` 只用于版面。

## 3 `history.json` — 历史同车型响应（Step 3）

```json
{
  "rows": [
    {"project": "蒙西矿业", "model": "WLR-5C(E)",
     "doc": "8、投标设备技术性能指标的详细描述-3.docx",
     "prio": 1, "no": "9", "param": "续航里程",
     "req": "续航里程 ≥120km", "resp": "矿井综合运行里程 ≥120km……", "dev": "无偏离"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `project` / `model` / `doc` | 来源三元组，缺一不可引用 |
| `prio` | 来源优先级，1 最高（新项目优先） |
| `param` | 参数名（历史行名称列冒号前） |
| `req` / `resp` | 历史原文，保留原样 |

## 4 `alias.json` / `hints.json` — 同义词与旁证关键词

```json
{
  "alias": {
    "续航里程（km）": ["续航里程", "续航里程（km）"],
    "电源系统总能量（kWh）": ["电池类型*", "电池箱总容量"],
    "车辆类别": []
  }
}
```

```json
{
  "hints": {
    "6.2.1": ["驾驶室"],
    "6.2.7": ["充电柜"]
  }
}
```

`*` = 复合行内含；`[]` = 确认无对应项。参考 `assets/alias-example.json`、`assets/hints-example.json`。

## 6 `matrix-spec.json` — 出表输入（Step 5）

```json
{
  "sheet": "车型标准响应对照",
  "note": "说明：标准车型答案列取自以往投标项目同车型的实际响应原文。",
  "rows": [
    {"sec": "5.1.1", "kind": "table", "orig_no": "15",
     "model": "矿用防爆指挥车 WLR-5", "sub": "动力与行驶系统",
     "part": "整车基本参数", "func": "续航里程（km）",
     "std": "矿井综合运行里程 ≥120km……",
     "req_body": "续航里程（km）：≥120",
     "resp_body": "续航里程（km）：≥120（矿井综合运行工况）",
     "dev": "无偏离"},

    {"sec": "6.2.6", "kind": "para", "orig_no": "",
     "func": "电驱系统", "req_body": "驱动电机为防爆永磁同步电机……",
     "resp_body": "驱动电机为……", "dev": "无偏离"}
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `sec` | 是 | 章节号，编号推导用 |
| `kind` | 是 | `table` / `para` |
| `orig_no` | table 必填 | 原文行号；para 可空（空即用条款号） |
| `req_body` | 是 | 要求正文，**不要带编号**，构建器会加 |
| `resp_body` | 否 | 响应正文，不带编号；空则响应列为空 |
| `dev` | 是 | `正偏离` / `无偏离` / `负偏离` |
| `std` | 否 | 标准车型答案（历史原文） |
| `no` | 否 | 显式编号，覆盖推导结果（用于原文异常场景） |
| `sep` | 否 | 编号与正文的分隔符，默认空格；`、` 用于条款号形态 |

`model`/`sub`/`part` 允许留空，构建器按上一行向下填充并纵向合并。

## 7 修订层 `revision.json`（可选但强烈建议）

```json
{
  "5.1.1#14": {
    "why": "招标要求仅涉及续航里程，说明不得引入电池自放电、三年衰减",
    "dev": "无偏离",
    "resp": "续航里程（km）：≥120（矿井综合运行工况）"
  }
}
```

键 = `条款号#行索引`（表格行 0 起；段落行 = clause 下标）。重建表格时按此覆盖，保证反馈不丢、可追溯。
