# 编号规则：只用招标原文的编号，加章节前缀

## 一条总则

**编号 = 招标章节号 + 招标原文编号。** 原文有号就带号，原文没号就用条款号，原文重号就保留重号。不重排、不补号、不合并、不自造复合定位号。

反面例子（真实发生过、被业务退回）：

- `5.1.2-04` —— 自造复合定位号，原文没有这个东西。
- 每张表都从 `1、2、3` 重新计数 —— 表间编号重复，无法定位。
- `5.1.1.1 1．参考型号` —— 章节号后紧跟原表号，双前缀。
- 把 `5.2` 排到 `6.2.16` 之后 —— 按车型归并打乱原文次序。

---

## 表格类：`<章节>.<原文行号>`

| 原文 | 表内编号 |
|---|---|
| 5.1.1 表第 1 行 | `5.1.1.1` |
| 5.1.1 表第 15 行 | `5.1.1.15` |
| 5.2 表第 19 行 | `5.2.19` |
| 5.3 表第 5 行（原文写了两次 5） | `5.3.5`（两行都用） |
| 注入子行（原 12 行拆成 12/12-1） | 都挂 `5.1.1.12` |

原文行号取单元格值，不按顺序数；续表续行沿用续行号（3→4 而不是回到 1）。

## 段落类：状态机推导

`scripts/numbering.py::derive_para_numbers` 实现，复刻招标文件自己的嵌套：

| 原文形态 | 编号 | 说明 |
|---|---|---|
| 本节内 `1．` / `1、` | `<章节>.1` | 开启一级组 |
| 上述一级组下的 `（1）` | `<章节>.1.1` | 嵌两级（如 7.1.1） |
| 本节无一级数字时的 `（1）` | `<章节>.1` | 括号即顶层（如 6.2.5.1、9.1） |
| 短标题括号（`（2）技术服务要求`，≤12 字、不以。结尾） | 成为父级 | 其下 `1、2、3` → `9.2.1` |
| 无任何编号的正文段 | `<章节>、` | 用条款号，如 `6.2.6、驱动电机……` |

已用真实标书验证：158 条要求，推导结果与人工整理版**逐条 0 差异**。

## 跨页续表：三条件同时成立才算

1. 续页首行首列是纯 1–2 位数字；
2. 该数字 = 上一张表最后一行号 + 1；
3. 首行第二列仍有内容（不是另一张表的表头）。

只满足 1、2 的情况（如备品备件表恰好从 1 开始）不合并；页脚孤立数字行先剔除，否则会打断逐字比对。

## 原文自身的编号异常：保留 + 报告

| 异常 | 实例 | 处理 |
|---|---|---|
| 同一行号出现两次 | 5.3 表"最高车速"与"最大举高"都写 5 | 两行都用 `5.3.5`，校验时用 `--allow-dup 5.3.5` |
| 同一条款下多段无编号 | 6.2.5 的电源安全句与电芯推荐句 | 两行都用 `6.2.5、`，校验时列入 `--allow-dup` |
| 条款内不再分子号 | 6.2.6 整条一段话 | 用 `6.2.6、`，不自造 `（1）` |

交付时要主动说明这些异常**来自招标文件本身**，不是整理错误；这比悄悄改成 1、2、3 更能经得起质疑。

## 两列对齐

编号同时嵌入「本次招标要求」与「投标人响应」两列的行首，**不单独成列**：

```
本次招标要求：5.1.1.15 续航里程（km）：≥120
投标人响应：  5.1.1.15 续航里程（km）：≥120（矿井综合运行工况）
```

- 响应为空时不加编号（不要留一个孤零零的编号）。
- 响应单元格内的说明层（优于补充说明 / 证明材料）不再重复编号。
- 组合时先剥离正文里可能残留的原编号，避免 `5.1.1.15 15、…`。

## 自检

```bash
python scripts/verify_matrix.py 表.xlsx --allow-dup <原文重号列表>
```

Gate B 会报：编号格式非法、同节断号、同节重号、要求/响应编号不一致、双前缀。断号一律视为错误；重号只在 `--allow-dup` 中列出时才放行。

## 上级编号不下沉（2026-10-21 业务二轮审查）

带前置章节号（（一）（二）…）的原文，其标题行与子级行的编号分工：

- **标题行**：`（二）供货范围` —— （X）级编号只出现在这一行；
- **子级行**：`1．矿用防爆指挥车：…` —— 保留自己的低级序号原样，**不重复**上级 `（二）` 前缀；
- 要求列与响应列同步处理（两列行首编号必须一致，见不变量 3）；
- 反例：要求列写 `（二）1．矿用防爆指挥车…` 会被退回——"（二）下面的子级前面去掉（二）级标题"。

生成器实现：拼行时用 `"%d．%s"`，不要写成 `"（X）%d．%s"`；校验用正则 `^（[一二三四五六七八九十]）\d` 扫两列残留。

## 一码两号（连写错号）的处置（2026-10-22 陈家沟项目）

原文偶尔把两个层级写成一行号，例如 `3.7.56 左右两侧具有倒车镜`、`1.13 接收处理各个零部件信息`（1.1 组内，实为 1.1.3）：

- **判定**：一个编号段里末位出现两位以上、且夹在连续序列中间（前有 3.7.4、后有 3.7.7），即为漏写分隔点；
- **处置**：**订正**为应有编号（`3.7.56→3.7.6`、`1.13→1.1.3`），并在说明行/汇报中披露原文号，方便回查 PDF；
- **前提**：必须先确认同号在该车型其他地方**没有合法占用**（如 `1.13 设计、制造中…` 是另一节的合法顶层条款），所以订正要按**行号**做键，不能按编号做键；
- 订正必须放在"父级标题判定"**之前**，否则层级深度按错号算，条款会被误判成组标题；
- 与"原文缺条"区分：订正针对**一码两号**；若原文整条缺失（如 3.7.5 驾驶室噪音只在他车型有），保留缺口并在汇报中列明，不要凭空补号。

## 表格来源参数的编号

参数表在原文无编号时，编号 = 参数节号 + 表内序号（`2.1…2.n`）。两种情况例外：

- 参数表排在 `1.主要技术参数` 标题**之前**（如 5 吨双向双头材料车），给 `1.x` 会与正文 `1.1` 重号 → **保留无编号**，按原文呈现；
- 参数表跨页续表时计数器顺延，不重新起号。
