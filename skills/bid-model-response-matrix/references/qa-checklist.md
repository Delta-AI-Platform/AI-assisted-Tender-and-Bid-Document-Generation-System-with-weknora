# 交付前校验清单

四道门，全部通过才可交付。命令都可直接运行（在技能目录或把 `scripts/` 加进路径）。

```bash
python scripts/verify_matrix.py 交付/表.xlsx --source tender_text.txt \
  --allow-dup 5.3.5,6.2.5 --report chk/校验报告.txt
```

---

## Gate A 结构

- [ ] 只有 8 列，顺序为 车型 / 子系统模块 / 部件模块 / 功能模块 / 标准车型答案 / 本次招标要求 / 投标人响应 / 偏离说明
- [ ] 表头下第二行是统一说明行（合并单元格），数据从第 3 行开始
- [ ] 行数 = 招标要求条数（表格行 + 段落条），无遗漏、无重复行
- [ ] 无空响应行（确实待确认的，必须显式写"待确认"）
- [ ] 无编号行 = 0（除原文本身以括号开头的行）
- [ ] 冻结窗格、筛选、列宽、边框未被破坏

## Gate B 编号

- [ ] 每行编号为 `数字.数字[.数字]` 形式，且以空格或顿号与正文分隔
- [ ] 同一节内编号连续，**断号 = 0**
- [ ] 重号只在原文自身重复时出现，且已列入 `--allow-dup`
- [ ] 要求列与响应列的行首编号完全一致
- [ ] 无双前缀（`5.1.1.1 1．`）
- [ ] 行序 = 招标原文节序（5 → 5.2 → 5.3 → 6 → 7 → 8 → 9），未被车型归并打乱

## Gate C 偏离与语义

- [ ] 正偏离条数 = 含"优于补充说明"的条数（两者必须一致）
- [ ] 每条正偏离都有可量化优势：`≥` 要求响应值更大，`≤` 要求响应值更小；**相等即失败**
- [ ] 每条正偏离的说明都出现本条核心词（功能名或要求正文的关键二元组）
- [ ] 无偏离行**不含**"补充说明"或"证明材料"
- [ ] 全表无"已满足"
- [ ] 说明中的主体词没有跨族串条（电机条不谈电池、续航条不谈电机）
- [ ] 负偏离（若有）写清实际值与差距

> Gate C 的"族词提示"是**建议**不是错误：如爬坡条提三电联调、DMS 条列全项功能，属于合理支撑。逐条读过后可放行。

## Gate D 原文逐字

- [ ] 段落条正文可在 `tender_text.txt` 中逐字命中（0 未命中）
- [ ] 表格条按"名称 / 指标 / 备注"分段也能命中
- [ ] 抽查 5 条编号与 PDF 原页截图对照，肉眼确认

## 人工必做（机器替代不了）

- [ ] **数值类**逐条对证书/检验报告：能量、续航、功率、尺寸、载重、爬坡、充电时间
- [ ] **正偏离**逐条朗读一遍，问"这句说的是不是本条"
- [ ] **无历史条目**标记清楚，交技术部确认
- [ ] **原文异常**（重号、无号、续表）在汇报中说明来源
- [ ] 业务改写稿的每一条都能在修订记录里找到 `why`

## 生成口径三处易错（2026-10 陈家沟项目补充）

### 1 断号判定：三个前提缺一个就满屏假报

- [ ] **组标题行也算号**：`3.29 防爆监控保护系统` 这类父级标题本身带编号，统计时必须计入序列，否则它自己就成了"跳号"
- [ ] **按车型/章节分组，不按"部件模块"分组**：同章 `3.x` 会跨多个部件，按部件分组就把一段连续号拆成几段，产生成片假断号
- [ ] **"全项目通用"不参与连续性判定**：总则、通用技术要求、备品备件等各节独立从 1 起号，直接跳过
- [ ] 剩下的断号才是原文缺陷，按"保留原文编号 + 汇报披露"处理，不要为了连续去改号

### 2 短应答：`原文 + ，满足招标要求。` 是退回高发项

长度阈值只是报警器（<20 字），真正要按句式改写：

| 句式 | 改写 |
|---|---|
| `参数名：值` | `我方投标产品{参数名}为{值}，满足招标要求。`（中文值不加空格） |
| 条件片段 `…达到77℃时；` | `…即自动报警并触发保护，满足招标要求。` |
| 陈述句 `驾驶室配置电动雨刷器；` | 补车型主体：`整车驾驶室配置电动雨刷器，满足招标要求。` |
| 资料清单 `投标文件 √ 必须` | `我方按要求提交{名称}，满足招标文件要求。`；`× 无需` 用"招标文件标注该项无需提供…" |
| 文件陈述 `本招标文件提出…` | `…，我方无异议。`（**不能**加"满足招标要求"） |

- [ ] 补主语前先判"是否已有主语"：句首是 `本/该/其/如/按/在/对/经/由/所/凡/每/各` 时**不得**前缀"我方/整车"，否则出"我方本招标文件…"
- [ ] 参数表合并单元格（首列留空）要继承上一参数名；`名｜子项｜值` 三列行写成 `名（内）`，否则出现 `投标产品：外 ≤6300` 这种残句
- [ ] `≤7300×1950×1960` 里的 `×` 不是"无需"标记，清单判定要用 `^[√×]\s*` 严格匹配

### 3 跨车型借用历史响应：先判"能不能借"，再判"像不像"

- [ ] 历史语料来自别的项目时，**设备不同就不借**：胶轮车的瓦斯报警响应不能拿去答移动变电站/馈电开关的保护条款
- [ ] 允许范围：本公司同车型（胶轮车、铲运机）的功能类条款 + 通用类条款（资料/包装/培训/质保/合格证/标准）
- [ ] 话题门控前先 `strip_device()` 去掉设备名，"矿用隔爆型锂离子蓄电池无轨胶轮车"里的"蓄电池"会让**每条**都命中电池类话题
- [ ] 锚点匹配按"关键词在句中**最先出现**"定主题，不要按锚点列表顺序取第一个命中；锚点命中但语料无对应响应时**就此结束**，不要顺延到下一个锚点（否则"辅助运输管理系统"会命中"运输/包装"）
- [ ] 通用词做锚点要加否定环视：`运输(?!管理|系统)`，否则"辅助运输"抢走包装运输响应

### 4 E 列只填"对得上"的，对不上的**留空**（2026-10-22 业务口径）

- [ ] 全表搜 `无同车型历史` / `无历史` / `暂无` / `—`，命中数必须为 **0**——E 列不写任何占位文字
- [ ] E 列非空条数应显著小于总行数；若命中率过半，基本是拿近似条款在凑
- [ ] 抽查 10 条"F 与 E 同读"：盖住编号后，E 能否当成本条的答复读通？读不通即错配
- [ ] 参数条（含 `≤ ≥ 不小于 不低于` 或带单位数值）默认**不填** E 列：要求 ≥100kW 而历史是 70kW，填上去就是虚假响应
- [ ] 程序性条款（品牌"参照或相当于"、资料补发、图纸复制、备件停产）默认**不填**：功能类响应套上去是答非所问
- [ ] 同一大话题下的**子项要分开**（制动系统构成 ≠ 制动距离 ≠ 静态制动力 ≠ 能量回馈），锚点必须带"禁含词"，否则一个 `制动` 锚点会命中整章
- [ ] 说明行不得写"标注无同车型历史"——表里没有这类文字，说明与实物不符

## 标记回收专项（业务退回标记版时）

- [ ] `parse_marked_review.py` 解析：黄色=缺失 / 红字·划掉=过度承诺 / 蓝字=业务终稿
- [ ] 黄色行先回招标原文确认原文内容，再逐条转化；标记版底稿可能比最新交付旧，先逐格 diff 分清"底稿旧"与"业务改动"
- [ ] 过度承诺修订逐条写 `why`（五类红线见 deviation-and-wording.md）
- [ ] 补齐章节后重跑四道门 + 编号核对，行数变化在汇报中列明
