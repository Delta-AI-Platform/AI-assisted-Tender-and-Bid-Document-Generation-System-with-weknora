# 匹配规则：宁可判"无历史"，不可给错来源

## 五级匹配（按顺序，首个命中即止）

| 级别 | 条件 | 可信度 | 能否作答案 |
|---|---|---|---|
| 1 参数名精确 | 功能名与历史参数名（去空格/括号/标点后）完全相等 | 1.0 | 能 |
| 2 同义词命中 | 命中同义词表中的别名 | 0.8 | 能 |
| 3 参数内含 | 别名带 `*`：历史行为复合行，其要求文本前 40 字含本参数名 | 0.8 | 能 |
| 4 关键词参照 | 段落条款，历史行的要求与响应同时含关键词 | 0.5 | **不能**，仅旁证 |
| 5 无历史 | 以上都不成立 | 0 | 由业务/产品资料填 |

## 为什么禁止模糊搜索

曾用"关键词包含"找答案，结果：

- 「总电压(V)」被匹配到历史「监控项目」行（因为响应里列了"总电压"）；
- 「电机控制器功率」被匹配到「电机额定功率」；
- 一条充电站条款被匹配到 WLR-5 的「**电池类型**」行。

这类错误的共同点：**看起来有来源，实际答非所问**。评审时很难发现，一旦被质疑，整张表的可信度归零。因此：

> 找不到精确或同义对应，就判"无历史"。空着比写错好。

## 同车型是硬门槛

- 只有同平台/同型号族的历史响应能当答案。WLR-5 → WLR-5C(E) 可以；WLR-5 → WC5JA 不行。
- 车型不同但结构相同的部件（如都用某型号制动器），也只能作为**业务确认后的依据**，不能自动匹配。
- 无同车型模板的车型（升降车、抓举车、充电站、尾气装置、通用条款），全部标"无历史"，响应来源写"产品资料/业务拟制"。

## 同义词表怎么写

```json
{
  "续航里程（km）": ["续航里程", "续航里程（km）"],
  "电源系统总能量（kWh）": ["电池类型*", "电池箱总容量"],
  "电机额定功率（kW）": ["驱动电机额定总功率（KW）", "电机额定总功率"],
  "转向器型式": ["转向助力", "转向器"],
  "灭火装置型式": ["配备自动灭火系统", "灭火装置"]
}
```

- 按优先级排列，第一个命中的用；顺序体现"越靠前越可能是同一项"。
- `"": []`（显式空列表）表示**确认模板里没有对应项**，直接判无历史，不做同名兜底。
- `*` 只给复合行用（一行里同时写了类型、容量、电压），且必须人工确认过包含关系。
- 同义词表是资产：下一个项目可直接复用并按新模板补充。

## 段落条款：旁证也要克制

- 历史模板多为参数表，只能为"该条款提到的能力"提供旁证，不能回答整段要求。
- 命中条件收紧为：关键词同时出现在历史**要求**与历史**响应**中，且响应不是"无偏离"。
- 同一关键词只挂一次，避免一条旁证在 8 个条款里重复出现。
- 只有同车型条款才允许挂旁证。

## 覆盖率怎么看

真实项目（158 条）的分布：

| 匹配方式 | 条数 |
|---|---|
| 参数名精确 | 2 |
| 同义词命中 | 20 |
| 参数内含 | 2 |
| 关键词参照 | 7 |
| 无历史 | 127 |

**80% 无历史是正常结果，不是失败**：招标技术条款大多是新车型/新配置。覆盖率的作用是告诉业务"哪 127 条需要人填"，而不是逼着算法去凑数。

汇报时要按车型给出"总数 / 有历史答案 / 有旁证 / 无历史"，让技术部知道工作量在哪。

## 输出字段

```json
{
  "id": "T-5.1.1-15",
  "match_type": "同义词命中",
  "confidence": 0.8,
  "hist_param": "续航里程",
  "hist_resp": "矿井综合运行里程 ≥120km……",
  "source": "蒙西矿业｜WLR-5C(E)｜8、投标设备技术性能指标的详细描述-3.docx"
}
```

`source` 必须三段齐全（项目｜车型｜文档），缺一段即视为不可引用。`confidence` 只用于排序复核队列，不用于自动决策。
