# 车型标准响应参考表

产出一张**逐条技术响应矩阵**。默认工作模式是“八列内部核对表”：Agent只建立要求、层级和历史参考，不替代业务人员填写本项目响应或判定偏离。

八列固定：`车型｜子系统模块｜部件模块｜功能模块｜标准车型答案（历史投标响应）｜本次招标要求｜投标人响应｜偏离说明`

## 默认模式：八列内部核对表

用户未提供一份已由业务人工核对完成的八列表时，必须执行以下边界：

- 覆盖技术部分的总则、供货范围、引用标准、运行环境、各车型参数、专项技术、质量售后和备品备件，保持招标原文物理顺序。
- 第1—4列全部填写为“车型 → 子系统模块 → 部件模块 → 功能模块”。分类只作左侧索引，不得据此调整第6列顺序。连续且完整父路径相同的同名单元格纵向合并；父级改变时子级不得跨组合并。
- 第5列只写历史响应权威库返回的精确同车型答案，或技能明确批准的同车型族答案，并保留来源三元组和记录ID。找到就直接使用；找不到就在机器清单中说明并保持表格单元格真正空白，不写“无历史”“待核验”等占位文字。
- 第6列逐字保留招标要求。编号按招标实际章节层级生成并放在同一单元格，例如第五章第一小节第一项为 `5.1.1`；不得自造多一级编号。原文无局部序号但属于该层级的项目，按实际连续次序编号。除剥离原局部编号并换成确认的完整层级编号外，文字、数值、单位、符号和顺序一字不改。
- 第7列“投标人响应”和第8列“偏离说明”全部留空，留给业务人工核对和修改。Agent不得执行该业务核对，不得预填“满足”“无偏离”或任何候选响应。
- 同时生成可编辑 DOCX 和 XLSX。PDF只可临时用于渲染检查，不得作为产物；内部JSON清单只用于追溯，不在网站产物区展示。
- 两个文件均标明“内部核对、未经业务审核、非递交稿”。未经人工核对的八列表不得转换为正式三列表，不得进入投标文件。

网站 Agent 必须先调用 `get_requirement_atomization_schema`，再调用 `build_requirement_atomization` 建立经门禁验证的条款拆分来源数据，并调用 `render_requirement_atomization_review` 输出六列审查表：`原文顺序｜层级编号｜条款类型｜适用对象｜招标要求原文｜来源页码及位置`。条款解析层不得套用八列技术响应核对表版式，也不得出现车型/子系统/部件/功能四级列、标准答案、投标人响应或偏离。层级编号单独保存，招标要求原文保留来源中的原局部编号和完整文字，不把补全编号写回原文。机器通过只代表原文、顺序、行边界和来源覆盖通过；对象归属的语义结论不得因存在来源引文就宣称正确。六列表机器门禁通过后直接检索历史答案并调用 `build_eight_column_internal_review` 出表，不为等待人工确认而暂停 AI 批处理。拆分按核对表的行边界逻辑：原表一行对应一个来源条目，正文按原条款或完整连续段落成条，不得把多条货物、多行参数或多个原表行合并成一条。原文不能确定时记录不确定项、保持逐字原文和原行边界并继续，不得沿用上一条语境猜测。八列表 spec 必须引用已通过的 atomization_path，并用锁定的 `technical-source-index.json` 中来源ID和逐字引文锚定每一行；第5列引用 `history-match-log.json` 中的权威记录ID。工具拒绝原文改写、跨车型历史、未通过原子化门禁以及非空的第7/8列。不得用通用表格代码绕过工具门禁。

只有业务人工交回已核对八列表，并明确要求继续形成正式响应时，才进入本技能后续的响应、偏离和正式表流程。以下涉及响应措辞、偏离判定和正式交付的规则均属于该后续模式，不能提前用于内部核对表。

## 三库边界与检索门禁

网站 Agent 固定使用三个独立资料库，禁止把不同用途的内容放在一个候选池里：

- `enterprise_facts`（企业事实库）：营业执照、企业证书、财务、人员、业绩、合同、授权与承诺等原件事实；
- `inspection_reports`（检验报告参数库）：车型、子型号、部件、参数、测试条件、报告编号和原件物理页；
- `history`（历史响应权威库）：人工核验过的标准答案、适用车型范围、版本和来源三元组。

用户已于 2026-10-24 明确确认三个库的数据均可由 AI 直接使用。执行中不得再以“等待人工批准资料、历史答案或既有映射”为由暂停或询问确认。已安装技能中的受控同义词表和批准车型映射直接使用并保留 mapping ID 与来源。找不到适用记录、原件页失败或规则冲突时，记录原因、保持第7—8列空白并继续下一条，直到全部条款处理完毕。

企业事实或检验报告候选必须调用 `search_evidence_candidates`，并按工具回执依次经过：`主体/车型过滤 → 关键词检索 → 本地向量召回 → 本地 rerank → 规则校验 → 哈希绑定原件页验证 → 证据适用性判断`。前五段只产生候选；原件页验证必须调用 `verify_evidence_original_page`，传入候选成员的真实 SHA-256、物理页以及待核对的主体、车型、参数和值。只有回执同时满足 `verification_status=verified_original_page` 与 `fact_use_allowed=true`，才能调用 `validate_evidence_applicability`，逐项核对招标原文锚点、对象类型、车型、子型号、部件、参数、单位和测试条件。只有 `applicability_status=applicable` 且 `comparison_allowed=true` 才能进入下一步结构化数值比较；任何 missing 或 mismatch 都必须拒绝该证据，不得自行创建同义词或车型映射。任一原件字段失败即弃用该页，不得用缓存文字、向量结果或历史答案补判。即使原件页和适用性都通过，也不得自动生成“满足”“无偏离”、证书有效或资格通过结论。检验报告必须同时一致：车型、子型号、报告编号、测试条件、参数名和物理页，不得跨报告拼值。历史响应不是本项目证据，企业事实和检验报告也不得反向写入历史标准答案列。

结构化比较只能调用 `evaluate_evidence_value_relation`，禁止模型自行心算后写结论。工具会重新执行原件页和适用性门禁；任一前置失败时 `mathematical_relation` 必须为 null，但必须记录缺项并继续下一条，不能中断整批执行。数值只允许明确的小数，支持 `ge/le/gt/lt/eq/between/covers`；枚举只允许 `enum_eq/enum_contains_all`。仅使用工具内受控单位换算，未知单位或不同量纲只跳过当前比较并继续。招标阈值、区间端点和单位必须能在逐字 `source_quote` 中定位。工具返回的 true/false 默认只表示数学或枚举关系。若本项目拟供车型尚未锁定，不得转换成偏离结论。若拟供车型已由项目选型记录锁定、证据车型与拟供车型精确一致、招标逐字要求及来源索引均有哈希锁定，且原件页、适用性与结构化比较全部通过，则批量任务必须传入 `locked_configuration` 并在同一次调用中自动形成结论；单条复核可调用 `conclude_locked_configuration_deviation`。关系 false 直接形成“负偏离”，关系 true 形成“无偏离”。机器结论进入内部逐行追溯台账；第7列投标人响应和第8列偏离说明仍按当前八列表人工核对边界保持空白。

证据任务应调用 `batch_evaluate_evidence_relations` 每批连续处理 1—20 条，并循环批次直到原子化条款总数全部被访问。`gap` 项只登记无适用证据及原因；`evaluate` 项执行原件页、批准映射、适用性和结构化比较；项目拟供车型已锁定时必须在同一项传入 `locked_configuration`，批处理工具自动形成“无偏离/负偏离”机器结论。单项 `item_error`、无适用证据或门禁阻断不构成整批失败，不得暂停或询问用户；记录后继续下一项。每批必须核对 `all_items_visited=true`，全部批次的任务 ID 数量必须等于待处理条款数量。批处理只形成内部机器证据台账，不得写入第7列和第8列。

八列表生成必须把全部证据批次路径写入 `evidence_batch_paths`。生成器要求证据批次合计对每个 `requirement_id` 恰好覆盖一次，并另存内部 `*.traceability.json`：逐条固定 DOCX 表格行、XLSX 行、条款 ID、招标原文哈希、历史匹配状态与权威记录、原件来源 ID/SHA-256/物理页/映射 ID/数学关系，或明确缺项、冲突、阻断及错误原因。追溯台账不得增加八列表列数，不得把机器关系写进第7列或第8列。缺少任一条款、重复 ID、历史状态缺失、原件页引用不完整或批次未完整访问时，拒绝生成新的八列表版本并修复台账输入。

历史答案匹配先把适用对象映射为批准的查询车型，再要求返回记录为该精确车型。WLR-5 → WLR-5C(E) 只允许使用已批准的 `WLR5-PLATFORM-001` 映射；映射后不得再次扩展到 WLR5B 等其他配置。参数只允许标题起始位置的精确名称或受控同义词；仅节号和空白不同的重复答案可视为等价并保留其中一份原文，数值、配置或实质表述不同必须标记冲突并留空。

交付物是这张表；拆模块、拆历史模板、记录来源，都是**找答案的手段**，其产物用于核查答案对不对，默认不进交付表。

## 不变量（破坏了就必须返工）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 行序 = 招标原文节序，禁止按车型/模块归并重排 | 归并曾把 5.2 挪到 6.2.16 之后，业务一眼看出不符合原文次序 |
| 2 | 编号 = 章节号 + 原文编号，不重排、不自造 | 曾自造 `5.1.2-04` 复合号，被要求"不能改动原有序号" |
| 3 | 编号嵌入「要求」「响应」两列行首，不单独成列 | 业务明确"序号不单独成列" |
| 4 | 原文无子序号时用条款号（`6.2.6、`），不自造（1）（2） | 条款号也是原文编号；自造会让条款数量失真 |
| 5 | 无偏离只写应答值，不写补充说明/证明材料 | 说明只用于解释偏离 |
| 6 | 正偏离必须有数值/能力优势，相等即无偏离 | 曾把"25 对 25"判成正偏离 |
| 7 | 说明主体 = 本条要求对象，范围限于本条话题域 | 续航条写电机、写电池衰减，是最典型的退回原因 |
| 8 | 只允许同车型取历史答案；找不到判"无历史" | 关键词模糊匹配会把"总电压"匹配到"监控项目" |
| 9 | 不虚构参数、证书、报告名、承诺 | 一旦被质疑，整表可信度归零 |
| 10 | 每条要求只答一次，不合并、不漏条 | "识别不全、无法一一对应"是业务第一条反馈 |
| 11 | 覆盖完整：总则、供货范围、引用标准、运行环境、备品备件明细等"非参数"章节也要逐条转化；章节标题行本身也成行，给节级响应 | 业务把每个无响应的标题行标黄"缺"——"招标技术要求需全部转化，不能缺少" |
| 12 | 低一级序号保留原文原样（备件组号"一、"、表内序号 1..n 原样呈现，不重排进新层级） | 业务明确"低一级的序号保留原样" |
| 13 | 偏离必须有色标，且**只改字体颜色、不加背景色**：正偏离 →"投标人响应"+"偏离说明"两列红字（C00000）加粗；负偏离 → 两列蓝字（0070C0）加粗 | 先要求"标红/标蓝"，再明确"只标红字体 不要标红背景"；底色会盖掉模块列的浅色分组，整表观感变花 |
| 14 | 章节标题行的响应列 = 复制本次招标要求原文，不写"我方完全响应本节全部要求"套话 | 业务："类似标题 响应处完全复制本次招标要求即可" |
| 15 | 子级行不重复上级编号前缀：（二）节下的条目写 `1．…` 不写 `（二）1．…`；（X）级标题只出现在标题行自己那行 | 业务："（二）下面的子级前面去掉（二）级标题" |
| 16 | 通用要求（总则/供货范围/引用标准/环境条件/备品备件等）的响应：参照历史投标响应，把招标的**要求句式**直接改写为**答复句式**（"供方应…"→"所供…为…"），内容完整不简写；**不写"我方承诺/我方保证/完全响应"一类固定前缀** | 业务："去掉我方承诺等固定性字词 是把招标要求表述 改为 答复表述" |
| 17 | 明细类条目（备品备件、供货清单等）的排版：**组标题单独成行**（要求=响应=照抄原文，如"二、制动系统"），条目行在组标题下用组内序号 **1．2．3．** 排开（**不带组号前缀**——组标题就在上一行）；响应逐条镜像要求（"1．提供X，单位：套，数量：1，原车原厂正品、随货提供。"），**禁止概况话术批量应答** | 业务："按照标题一列 底下 12345678排开逐条响应"＋"响应要和要求一样 不准这样偷懒 概况填写"；组号+序号拼一行（"二、制动系统 序号1：…"）被否 |
| 18 | 版式按 `references/standard-template.md` 出厂即定稿：单 sheet「车型标准响应对照」、8 列固定列宽、表头 D9E2F3、模块列 FCE4D6、说明行 A2:H2 合并、**冻结 E3**、**不加自动筛选**、只允许偏离两列改字色 | 业务："这是标准模板"；冻结位置若在插行前设置会漂到表尾，筛选会把合并的说明行当数据行过滤 |

细则见 `references/standard-template.md`（版式定稿）、`references/deviation-and-wording.md`（偏离与措辞）与 `references/numbering-rules.md`（编号）。

## 标准模板（照此产出，勿另立版式）

版式定稿见 `references/standard-template.md`，六类行型照填：

| 行型 | 要求列 F | 响应列 G |
|---|---|---|
| R1 说明行（A2:H2 合并、斜体） | 历史来源与配色图例说明 | — |
| R2 章节标题行 | 原文标题 | **= 原文标题**（照抄，不写套话） |
| R3 参数/条款行 | 原文（行首编号） | 编号 + 答复句式取值 |
| R4 明细组标题行 | 「一、行走/转向系统」 | **= 原文组标题** |
| R5 明细条目行 | 「1．名称；单位：套；数量：1；备注」 | 「1．提供名称，单位：套，数量：1，备注」 |
| R6 注释行 | 「注：…」原文 | 答复式复述承诺 |

画布与样式一次性照抄：8 列固定列宽、表头 32 高 D9E2F3、模块列 FCE4D6、说明行 42 高、**冻结 E3**、**不加自动筛选**、正偏离红字 / 负偏离蓝字均不加底色。

## 工作流

### 1 抽取招标要求（逐字、按序）

```bash
python scripts/pdf_table_dump.py 技术部分.pdf -o tables.json
python scripts/pdf_text_dump.py  技术部分.pdf -o tender_text.txt
```

表格用 `pdf_table_dump.py`（按三条件拼接跨页续表、剔除页脚数字）；正文切分为 `table`/`para` 两类节，段落保留原文编号。四个高频坑（标题等于正文被判重、标题句中断行、正文是上句续行、续表被当新表）见 `references/sop-workflow.md`。

产出 `requirements.json`（`references/data-schema.md`）。

### 2 拆模块（只标注，不排序）

车型 → 子系统 → 部件 → 功能。功能名优先用原文行名/条款题名。产出 `module_dict.json`，确认粒度：约 8–15 子系统、20–35 部件、60–90 功能。

### 3 拆历史模板

把历史同车型响应表按同一词表切开，每条保留 `project｜model｜doc｜param｜req｜resp`。来源三元组缺一不可引用。产出 `history.json`。

### 4 逐条对应

```bash
python scripts/match_history.py --req requirements.json --hist history.json \
  --alias assets/alias-example.json --hints assets/hints-example.json \
  --same-model WLR-5 -o match.json
```

四级：参数名精确 → 受控同义词 → 标题起始位置的受控复合项（`*`）→ 无历史。关键词或向量召回只用于找候选，不能直接写入第5列。禁止跨车型、禁止正文中任意包含即匹配。无历史属正常，覆盖率用于分配人工工作量，不是失败指标。见 `references/matching-rules.md`。

### 5 组装响应

取值优先级：业务已确认改写 → 同车型历史答案 → 产品资料/证书实测值 → 空（标待确认）。

```bash
python scripts/build_matrix_xlsx.py matrix-spec.json -o 交付/车型标准响应参考表.xlsx --strict
```

构建器强制执行规则 2–8：推导编号并嵌入两列、剥离无偏离说明、清除"已满足"、模块列填充合并、正偏离缺说明即报错。

### 6 四道门校验

```bash
python scripts/verify_matrix.py 交付/车型标准响应参考表.xlsx \
  --source tender_text.txt --allow-dup 5.3.5,6.2.5 --report chk/校验报告.txt
```

- **A 结构**：8 列、行数、空响应、无编号行
- **B 编号**：连续性、断号、重号、两列对齐、双前缀
- **C 偏离**：数值方向、说明核心词、无偏离带说明、已满足
- **D 原文**：段落条逐字命中源文本

机器过完，人工必做两件事：数值类逐条对证书；正偏离逐条读一遍问"说的是不是本条"。清单见 `references/qa-checklist.md`。

### 7 业务标记回收（用户在 xlsx 上的批注即修订指令）

```bash
python scripts/parse_marked_review.py 已标记.xlsx -o ref/marked_issues.json
```

标记口径：**黄色填充 = 缺失需补齐；红字/划掉 = 过度承诺需去除；蓝字等改写 = 业务手写终稿**。
必须 `rich_text=True` 读取，否则格内局部红字/划掉读不到。产出的 `final_text`（保留片段拼接稿）
按"条款#行下标"写入修订层 `resp` 并附 `why`；黄色行对照招标原文补全（先回原文确认原文内容，再逐条转化）。
真实案例：一轮标记回收出 7 处过度承诺（照抄推荐品牌清单、括注数值重复、要求外功能"接近安全防护"、
"无条件上传+定位+60s 频率"整段指标承诺）与 17 个黄色缺失行（总则~环境条件整章、6.3/6.4 标题行、备品备件明细 176 条）。

### 8 交付

默认单 sheet xlsx。汇报：总条数、偏离分布、来源分布（历史/旁证/无历史）、原文自身编号异常、待业务确认清单。

## 返工的最小改动原则

| 反馈 | 改哪里 |
|---|---|
| 说明写错主体/超范围 | 修订层 `revision.json` 的该条 `resp` |
| 编号不对 | `numbering.py` 规则或 `requirements.json` 的原编号 |
| 次序不对 | 输出顺序（禁止改数据顺序） |
| 偏离判定不对 | 该条 `dev` + 依据，不改文字掩饰 |
| 原文识别错 | Step 1 的要求数据，不要在 xlsx 里打补丁 |

每次改写都写 `why`，保证复审可回答"为什么这么改"。
